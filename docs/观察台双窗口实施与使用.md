# 双窗口观察台：实施与使用

实施日期：2026-10-11。依据 `docs/design/观察台双窗口与对局归档方案.md`；实战记录采用一个 `YYYY-MM-DD` 日期目录，不采用年/月/日多层目录。

## 启动

双击 `launch/start_observer.cmd`：检查并按需启动执行服务（18766）、观察台服务（18767），打开独立 WPF + WebView2 实时窗口。使用项目内的 Anaconda 环境与 .NET 运行时，不向全局 Python 安装依赖。重复启动通过窗口互斥锁避免出现多个观察窗。

双击 `launch/start_history.cmd`：在系统默认浏览器打开完整历史页面。也可以在侧窗点击“完整页面”；页面按钮携带本局、幕次、节点、到访和决策标识。

命令入口：

```powershell
.runtime/conda/python.exe -X utf8 src/python/tools/runtime/start_observer.py
.runtime/conda/python.exe -X utf8 src/python/tools/runtime/start_observer.py --history
.runtime/conda/python.exe -X utf8 src/python/tools/runtime/start_observer.py --both
```

侧窗可以移动、调整大小、置顶、贴左/贴右、折叠和调整字号。位置配置在 `.runtime/local/observer-window.json`；WebView2 缓存在 `.runtime/cache/observer-webview/`。关闭窗口/网页不停止服务、不改变游戏控制、不自动开始对局。独立窗口使用 Windows 正常桌面权限；受限沙箱可能阻止 WebView2 创建子进程。

## 实时与历史

侧窗展示当前公开状态、资源、计算候选、伤害/格挡/失血/收益等变量、明确登记的 AI 选择与理由、执行状态、最近时间线和展开资料。报告与当前状态版本不同时显示过期提示。没有登记选择时不编造理由；回到菜单后不把上一局决策当成当前决策。

取消“跟随实时”会冻结侧窗，点击“返回实时”恢复。使用 SSE 推送已持久化事件，带游标重连；同时保留低频状态刷新和断线提示。

完整页默认进入对局总览，默认不跟随新对局。支持日期、职业实体 ID、进阶、状态筛选，排序及分页。点击一局后按动态幕次、地图修订、节点和到访筛选记录；兼容第四幕及更多幕。未读取的地图不补造。

节点时间线可打开完整公开状态、计算报告、评分分解、条件概率、AI 工具资料、选择理由和动作回执。超出首批时间线范围时可继续加载；大报告按点击加载。逐房间统计包括观察到的敌人、最大回合、生命变化和记录跨度；生命变化不等于敌人造成的战损，记录跨度不等于连续战斗工作时长。

## 存储

```text
data/runs/
  2026-10-11/
    run_<稳定ID>/
      manifest.json
      summary.json
      timeline.jsonl
      maps/act_000/generation_<ID>.json
      snapshots/<内容哈希>.json
      decisions/<事件ID>.json
      choices/<事件ID>.json
      actions/<事件ID>.json
      outcomes/<事件ID>.json
      events/<事件ID>.json
      provenance/references.json
      provenance/policies/<哈希>.json
```

存档稳定身份优先；没有稳定身份的旧资料只按启动会话分组，不猜测跨重启关系。游戏开始时间确定日期；缺失时用首次观察日期并标注。跨午夜续档不移动已有目录。同一房间跨重启会形成新的到访尝试。

菜单会话与实战总览分开。回放继续留在原回放区域，不转成实战；知识库仍在 `data/knowledge/`。`.pending/` 保存未成功归档的记录，恢复只补写资料，不重放游戏动作。

原始 JSON 是依据，SQLite 索引位于 `data/indexes/run-history.sqlite`，可以重建。完整快照按内容去重，计时字段不使相同游戏状态重复存储，也不会令游戏动作的状态版本过期。

总览和详情展示职业、实际进阶、进度、结果、游戏计时、观察到的自动控制时间、缺口、计算统计、资源与版本。缺少开始/结束或终局证据时显示未知；断线、正常退出和暂停不等于失败/放弃。自动运行计时只累计同一次连接会话中连续、启用自动且游戏未暂停的短采样区间；它是已观察时长，不是精确的 AI 推理计时。

## 指定记录与备份

- 桌面“打开记录”选择对局 `manifest.json`，验证后复制到归档区并打开；原目录保留。
- 网页“打开归档包”选择 ZIP。格式、体积、路径、快照引用和指纹验证后导入，标注导入来源。
- “导出本局归档”下载这一局的 ZIP，包含文件 SHA-256 清单，不包含鉴权 token、本机配置或全量知识库。
- 同 ID 不同内容保留独立冲突副本；导入记录不作为当前实时局，不自动加入评分校准样本。

## 迁移与恢复

旧记录先预览再复制；实战决策/观察按稳定 ID 归组，选择和结果按精确决策 ID 关联。无法可靠归局的条目在迁移结果中列出，回放保留原位置。

```powershell
.runtime/conda/python.exe -X utf8 src/python/tools/archive/migrate_run_archives.py
.runtime/conda/python.exe -X utf8 src/python/tools/archive/migrate_run_archives.py --apply
.runtime/conda/python.exe -X utf8 src/python/tools/archive/rebuild_run_index.py
```

重建索引从原始事件文件读取，不依赖 JSONL 尾部，因此损坏的时间线尾部不会阻止打开已有事件；原时间线保留。崩溃留下首份事件但没有 manifest 时，可重建标注为 `recovered_partial` 的清单。文件损坏会报告问题，不能恢复不存在的资料。

如果 SQLite 文件本身损坏，先关闭记录服务，再执行 `src/python/tools/archive/rebuild_run_index.py --quarantine-corrupt-index`；旧索引及 WAL/SHM 移到索引目录下的 recovery 备份目录后重建。实战文件不删除。
