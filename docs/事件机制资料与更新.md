# 全量事件机制资料

事件当前可见选项、格式化效果、实际卡牌/药水/遗物及动态数值，以实时游戏快照为准。本地事件资料补充尚未到达阶段的效果、费用公式、条件、候选池、随机规则及退出路径。源码初始化值不能代替当前值。

## 本轮覆盖

当前安装版本收录 57 个普通/特殊事件，199 个本地化选项。197 个选项已对应当前源码的构造或辅助生成逻辑；2 个仅存在于本地化中，在普通页面和 Agent 查询中排除。假商人使用自定义布局，没有标准选项列表，但保留库存、准入、投药水后的战斗与奖励逻辑。

`data/knowledge/behavior/catalog.json` 中每个事件新增 `event_model`：

- `variables`：原始定义、初始值、随机范围、更新操作、后续条件数值表和展示说明。
- `arrays`：按阶段索引的费用、伤害等。例如巨大花卉奖励为 35/75/135 金币，深入伤害为 5/6/7。
- `methods`：参数、泛型类型参数、即时效果、赋值与递增、条件、循环范围、辅助调用、返回值、switch 分支、随机调用、奖励生成/筛选操作和后续阶段。
- `bindings`：选项键或生成表达式、处理函数、闭包参数及条件。支持插值键、字符串拼接、枚举辅助函数、动态标题、泛型遗物选项及传送带的加权菜品。
- `property_rules`：属性中的筛选和随机逻辑。例如药水兑换的稀有度及卡牌类型规则。
- `state_fields/state_aliases`：事件阶段次数等实例字段及属性别名。
- `unresolved`：未识别的选项绑定或未声明的显示变量，供版本更新审计。

事件同时附带引用的附魔/能力资料及涉及怪物的血量范围。休息治疗引用本机对应辅助函数，保留遗物等 Hook 修正，不能只按固定 30% 当作最终治疗量。

## 代表性规则

深渊浴场每次获得 2 最大生命，初始伤害 3，每次伤害增加 1。剧情页次数封顶不代表伤害停止增长。原有已审查模型还处理增加最大生命时的回血及退出回复。

真理石板初次损失 3 最大生命，后续费用为 6、12、24，以及当前最大生命减 1。随机升级与最后的全部升级、结束条件、不能承担费用时的死亡路径均保留。错误状态的源码兜底值保留在工程证据中，不作为正常费用阶段展示。

滑脚木桥伤害为 3 + 坚持次数，并更新待移除牌。候选池包含移除资格和跳过记录；不能将随机牌写死为某张卡。

无尽传送带资料包括每次支付、金鱼免支付、菜品权重、资格筛选、排除上次菜品、强制菜品、领取后重新生成选项和退出。菜品单独效果不能替代共同支付与重复流程。

沉没雕像的金币为 101–121，淹水金库小箱为 52–67、大箱为 303–363。这些是随机生成范围，本次已生成值仍以游戏实际描述为准。固定范围整数每个结果的概率可提取；动态候选池或加权抽取保留筛选和分母表达式，不能编造固定概率。

## Agent 与页面

只发送当前事件的资料，当前 57 个事件分别查询均能进入 64 KB 行为资料预算。整体 Agent 上下文仍受原有 180 KB 限制。

Agent 获取结构化机制和压缩后的源码控制流程依据，不获取完整本地化剧情。条件、早退、复杂属性、回调和辅助函数不能仅凭一张扁平效果列表判断。

桥接 0.29.0 额外读取事件数值/布尔实例字段，StringVar 导出实际字符串而非基类数值 0。查询结果提供 `observed_variables`、`observed_state`、`observed_option_keys`；构建不匹配时不注入当前值。默认值和当前值分开放置，查询不会修改原始百科。

普通百科页提供“事件数值与变化规则”和每个选项的“具体效果与后续选择”。实际 JSON、完整证据仍可从工程视图查看。

## 更新

游戏更新后，先刷新基础百科，再运行：

```powershell
.runtime/conda/python.exe src/python/tools/knowledge/export_behavior.py
.runtime/conda/python.exe src/python/tools/knowledge/audit_events.py
```

导出器从当前游戏 PCK、本地化和匹配 DLL 的反编译源码重新生成机制；保存来源摘要和历史版本。审计结果位于 `data/knowledge/coverage/event-audit.json`。当前未绑定/未声明显示变量审计为 0；这只是抽取完整性指标，不是任意 C# 语义或概率已精确模拟的证明。

## 计算边界

这轮补的是完整事件机制参考资料与实时值绑定，不是通用 C# 执行器。AI 可据后续公式和条件比较选项；计算器仍只执行已经审查的事件规则。复杂随机奖励、遗物 Hook、生成卡的动态改造等保留源码和筛选证据，尚未全部转换为精确收益模型。不能因为没有未声明占位符，就宣称所有事件都能自动证明最优选择。
