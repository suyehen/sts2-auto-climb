# 事件接口与验收

0.6.0 支持标准 NEventLayout 的事件读取与按钮选择。构建零警告零错误；41 项 C# 与 9 项 Python/MCP 检查通过。已部署并通过标准事件选择、结算及返回地图的真实验收。

## 读取

state.event_screen 提供事件实体 ID、标题、当前页描述、布局类型、完成状态及选项。每项提供标题、含当前动态数值的描述、锁定状态、是否继续、游戏标记的致命风险、遗物 ID 和 hover_tips。普通文本提示导出标题与说明，卡牌提示导出完整卡牌资料。hover_tips_complete=false 表示存在未适配的提示类型。

标准按钮 OnFocus 使用 Option.HoverTips 创建悬浮窗，桥接读取相同对象，因此读取悬浮内容不需要移动鼠标。描述来自当前事件页和选项，动态变量已由游戏 UI 填入。只读取当前呈现信息，不预知事件回调中的随机结果或后续隐藏页面。

## 执行与完成

choose_event_option 与 proceed_event 使用原动作请求结构、target_id=null。要求单人、事件为当前活动界面、按钮可用且未锁定、入场动画完成、无地图/转场/弹窗覆盖、游戏与事件任务空闲。派发使用按钮 ForceClick，正常经过事件同步器、历史记录和 BeforeChosen。

完成必须等待当前事件任务结束、选项页面改变并出现稳定的新选项、地图或战斗决策点。不能以 WasChosen 或出现新按钮单独作为完成依据。删牌、升级、选牌等尚未适配的子界面及弹窗返回 needs_user_input，并保留执行槽；处理后查询原 request_id。同请求 ID 不重放。

自定义事件布局、古神对话等特殊输入和嵌入式战斗尚未验收；不应据此宣称支持全部事件。

## 知识与决策

无需先为每个事件手工编写知识。实时事件文本、悬浮信息、角色资源和牌组是当前决策依据。知识库可补充公开机制、长期影响、概率与策略经验，按游戏版本和事件/选项 ID 索引，与实测轨迹分开保存。若知识与实时数值不一致，以当前游戏信息为准并标记差异。

悬浮提示说明效果和引用物品，但不保证随机结果，也未必解释全部后续影响。缺失信息必须标为未知，不能把经验推断伪装成当前明确收益。知识检索与牌组计算仍未实现；目前由 Codex 根据已读取信息逐步选择。

## 真实验收结果

Codex 自动续档至第 3 层“光与暗的门扉”，读取当前页以及“随机升级 2 张牌”和“选择移除 1 张牌”的具体描述。当前两项均无额外 hover_tips，非空悬浮数据尚未实测。

非法动作及旧状态请求分别返回 INVALID_ACTION、STALE_STATE，均未派发且完整状态未变。选择光之门后等待正常事件任务和下一页，回执 completed；恰好打击与痛击升级至 1。相同请求再次提交返回相同回执，状态与版本未变。随后 proceed_event 返回地图，ready=true、busy=false；控制已暂停，血量 57/80、金币 112、牌组 12 张。

证据：.runtime/logs/event-live-verification.json、event-choice-verification.json、event-negative-verification.json。删牌分支、非空悬浮提示和特殊布局不在本次真实验收范围。

### 非空悬浮提示真实验证

0.8.0 进入第 6 层淹水灯塔，读取装瓶选项的发光水提示（消耗手牌、抽 10 张），以及攀爬选项的菲涅耳透镜机制和灵巧 2 说明，当前动态代价为失去 13 最大生命。提示类型和内容均成功导出，hover_tips_complete=true，事件未执行。证据见 .runtime/logs/event-hover-live-verification.json；尚未逐字与鼠标实际悬浮画面人工核对。
