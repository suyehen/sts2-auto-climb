# 本地百科资料库

游戏模组负责导出游戏自身的说明，Python 保存带版本的本地 JSON，Codex 经 MCP 按需查询。查询不连接游戏，不需要游戏运行；刷新需要兼容模组已加载，且游戏处于主菜单。

## 文件与职责

- `src/csharp/Knowledge/Encyclopedia.cs`：只在 Godot 主线程访问模型，每个计时周期最多导出 12 个条目；HTTP 线程读取缓存 JSON。
- `src/python/src/autoslay/knowledge_base/catalog.py`：校验、原子保存、历史备份、查询和刷新客户端。
- `data/knowledge/catalog/encyclopedia.json`：当前本地百科。
- `data/knowledge/catalog/history/`：成功刷新前的历史文件。
- `src/python/tools/kb_admin/export_encyclopedia.py`：手动导出/刷新命令。
- `src/python/src/autoslay/mcp/server.py`：`query_encyclopedia` 与 `refresh_encyclopedia` 工具。

## 导出范围

导出当前存档已解锁的卡牌、药水、遗物。卡牌包括基础版及第一次升级后的副本，费用、目标类型、关键词、动态变量基础值、相关悬浮提示；药水包含使用类型、目标类型与提示；遗物包含说明和相关提示。

元数据记录游戏版本、资料格式版本、语言、导出时间、解锁范围和来源会话。未解锁内容不在此范围。没有读取抽牌顺序、随机数或隐藏战斗信息。

百科用于规则说明查询，不表示条目已经支持数值模拟。战斗中的当前费用、伤害、状态、遗物计数仍以实时快照为准。无限升级卡只收录基础版和第一次升级；不假设其后所有等级相同。悬浮提示中未适配的提示类型保留 `supported=false`。

## 查询与更新

Codex 使用 `query_encyclopedia(query, category, limit, expected_game_version)`。优先传完整实体 ID，例如 `CARD.STRIKE_IRONCLAD`；也支持名称/关键词子串查询，类别可为 `card`、`potion`、`relic`。查询上限 50 条，避免整本资料进入上下文。应传实时快照的 `game_version`，版本不同会返回警告；省略时 `version_matches=null`，不能解读成版本一致。

显式更新入口：MCP `refresh_encyclopedia()`，或在主菜单执行：

```powershell
& .runtime/conda/python.exe src/python/tools/kb_admin/export_encyclopedia.py --refresh
```

刷新读取最新已解锁内容及当前语言，并等待新的导出代次，避免把旧缓存当成刷新结果。完整校验成功后才备份旧文件并原子替换；导出错误、空资料、重复 ID、超时或保存失败均不覆盖旧资料。备份失败也不替换。此入口不续档、不改变控制模式、不出牌。

游戏更新后的流程：先验证并适配 C# 模组，再进入主菜单刷新，核对新文件的版本与导出结果。当前模组明确支持游戏 0.111.0；更新入口不等于可以跨任意游戏版本自动适配。解锁进度或语言变化也可通过此入口刷新。

资料查询、可执行效果规则、评分策略相互独立；更新百科不会自动改动 `rules` 模块或选牌评分权重。暂时使用实体 ID 和关键词精确检索，无向量数据库依赖。
