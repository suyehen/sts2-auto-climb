# 药水接口与验收

0.10.0 针对游戏 v0.111.0 实现，代码在 src/csharp/bridge/Commands/PotionCommands.cs 与 PotionRules.cs。已部署并实测迅捷药水的使用、目标保护和重复请求。发现展示卡牌导致状态版本变化的问题，0.10.1 已修复并构建（零警告零错误，76 项 C# 与 9 项 Python/MCP 检查通过），待重启部署验证。丢弃和替换尚未实测。

state.player.potions 保留 entity_id，并新增 instance_id、真实 slot、标题、动态描述、hover_tips、usage、target_type、queued、target_supported、usable、discardable、use_action_id 和 discard_action_id。player.potion_slots 表示栏位容量。槽位来自当前游戏持有列表，不把过滤后的药水序号当作槽位。

新增 use_potion 与 discard_potion，沿用动作请求格式。目标必须来自 legal_actions；Self 可 target_id=null，由游戏正常入口归一化为玩家；敌方单体目标须传实例 ID；群体药水无目标。AnyTime 药水可在受支持的稳定战斗外界面使用，CombatOnly 只在稳定玩家回合使用，Automatic 不提供手动使用动作。位置目标药水尚未支持。

使用调用 PotionModel.EnqueueManualUse，保留 BeforeUse、IsQueued 与正常 UsePotionAction 同步和效果链。通过队列的 ActionEnqueued 记录该入口创建的实际动作，等待它完成。丢弃构造普通界面同样使用的 DiscardPotionGameAction，走正常同步队列、PotionCmd 和钩子，不直接改药水列表。执行前重新检查持有对象、槽位、排队状态、玩家 CanUseOrRemovePotions、自定义可用性、目标和稳定决策点。

完成必须满足动作 Finished、原药水已离开持有列表、队列空闲及下一稳定决策点就绪。仅药水图标消失不能提前认定效果结束。额外选牌或模态、等待超时返回 needs_user_input，保留原请求并要求查询原 ID；不自动重试或再次消耗。

替换为两步显式决策：先丢弃一瓶，再领取奖励或购买新药水。满栏时 PotionReward 不再提供领取动作，以免进入未适配的满栏流程。不得在物品不可用、转场、商店动画、事件待结算或选牌子界面中操作。

同时补齐当前遗物的动态描述与关联 hover_tips、可见状态效果的名称及实际 hover_tips，以及意图 GetHoverTip。仅导出游戏界面可见信息；通用 Buff/Debuff 意图的提示仍可能没有具体效果，不推断隐藏下一招或随机结果。

待真实验收：续档第 9 层读取迅捷药水、稳定血清与敌方噬尸蛞蝓的提示；使用合适药水核对消耗、手牌或状态变化；重复请求无重放、非法目标/旧状态拒绝；后续在合理替换时验证丢弃与领取。自动药水、位置选择、药水额外选牌和多人不在当前验收范围。
