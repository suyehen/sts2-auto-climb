# 机制覆盖与动态状态

机制执行直接使用现有代码定义，不存在独立的兼容规则库。详见[机制大全](机制大全.md)和[统一机制模型](全量卡牌遗物药水效果模型.md)。

覆盖报告中的 `defined` 表示存在本地代码定义，`missing_mechanic` 表示缺少定义。`reference_only` 表示仅有参考资料。这些状态用于说明覆盖，不是实体审批或执行开关。

桥接读取怪物实例的实际字段、遗物计数和卡牌原始动态变量。状态跟踪按会话、战斗实例和状态版本隔离；未观察的值不使用初始值或意图猜测，重复与倒序快照不会覆盖较新的记录。

抽牌、未知随机结果、新生成手牌实例和无法还原的取整数值可以产生观察边界。缺失机制会阻止精确推演；不会按零效果继续。

游戏更新后需要更新桥接和资料，并核对代码中的机制定义。全局版本检查防止旧代码被用于新游戏，资料指纹用于版本与内容溯源，不再决定单个实体是否获准执行。

桥接还导出公开战斗计数、虚弱与脆弱的持续时间跳过标记，以及实际奥斯提生命状态。缺失公开历史时，依赖出牌或抽牌次数的效果拒绝计算。宠物类型或宠物能力未实现时，同样明确阻止精确推演。每场战斗一次的遗物使用实际内部布尔状态，不以展示计数或默认零值替代。
