# 主菜单接口（0.4.0）

0.16.0 更新：新增带默认角色/进阶的 `start_new_run` 入口与独立、需明确授权的 `abandon_run` 动作。下文“没有放弃工具”描述是 0.4.0 的历史边界；当前行为见 [新局默认配置与验收](新局默认配置与验收.md)。

适配游戏 v0.111.0；标准单人模式。包含之前的战斗与基础奖励接口。

## 工具流程

使用现有 `get_state`、`set_control_mode` 和 `act`。主菜单增加 `state.menu`，含未完成存档是否存在、存档是否可加载、角色选项、所选角色、当前与最高进阶。按活动界面返回 `main_menu`、`singleplayer_menu` 或 `character_selection`。

动作请求的 `run_id` 使用最新快照的 **`state.command_context_id`**。对局中该字段等于真实 `state.run_id`；没有对局时是当前菜单实例 ID。`state.run_id` 在主菜单仍为 null，不要编造对局 ID。会话、状态版本、合法动作和请求去重保护继续生效。

| action_id / 类型 | 行为 |
|---|---|
| continue_game | 使用原有异步读档流程继续当前存档，等待加载与转场完成 |
| new_game | 点击主菜单单人游戏，进入模式或角色选择 |
| standard_run | 进入标准单人角色选择 |
| character_实例ID / select_character | 选择界面已解锁且未选中的角色 |
| ascension_up / ascension_down | 点击现有箭头调整一级进阶；范围由游戏解锁状态决定 |
| embark | 以当前角色和进阶出发；等待新局加载完成 |

每一步必须读取新状态；没有存档时才提供 new_game 和 embark。游戏本身会在已有存档时隐藏新游戏按钮，桥接也执行同样的保护。**没有放弃、删除或覆盖现有存档的工具**。创建新局后可能停在尚未支持的涅奥/事件界面，此时不提供后续动作。

菜单控制仅在实际活动界面、非转场、无模态弹窗及非暂停时执行。只支持单人角色选择，不向多人大厅派发。无法加载的存档、首次教程或其他未支持界面需人工处理；同一请求继续查询，不能因超时重开一局。

## 实现与验证

`MenuCommands.cs` 集中菜单适配。续档复用原有 `OnContinueButtonPressedAsync`；其他操作复用原有按钮/角色选择逻辑。私有成员读取集中在版本固定的 UI 适配中，游戏更新后需重新适配。

构建零警告零错误。23 项 C# 检查和 9 项 Python/MCP 检查通过；菜单新增检查包括现有存档、多人大厅、弹窗/转场和锁定角色阻止出发。真实续档和新局验收分别记录，不能互相替代。

2026-10-08 真实续档已通过：0.4.0 启动后，主菜单正确报告存在可加载存档，启用控制后合法动作只有 continue_game。Codex 经真实 MCP STDIO 自行续档，恢复到第 2 层、进阶 10、血量 57/80 的奖励界面；请求在加载完成后返回 completed。完全相同请求再次提交返回原回执，没有重新加载。现有存档保护已核对；没有存档时的新局创建、角色和进阶调整尚未进行真实操作验收。

证据：`.runtime/logs/menu-reward-live-verification.json`、`menu-continue-completed.json`、`menu-continue-duplicate.json`。

验收：

1. 部署后启动，确认版本 0.4.0 和默认 paused。
2. 读取主菜单，核对存在存档时只有续档动作，新游戏不可用。
3. 由 Codex 启用控制并提交 continue_game，确认真实进入同一存档，且加载完成前不接受新动作。
4. 使用完全相同请求参数重提交，确认不会再加载一次存档。
5. 没有未完成存档时，验证 new_game → standard_run → 角色 → 进阶 → embark；当前已有存档时不为了测试而删除它。
