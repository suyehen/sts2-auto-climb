# 机制大全

实体效果声明以 `data/knowledge/models/game-0.111.0.json` 为来源，公共操作由现有 rules/simulation 核心执行。机器可检索的规则说明、对应实现和已知边界统一维护在 `data/knowledge/mechanics/game-0.111.0.json`，由统一知识库的 `get_mechanics` 和机制检索读取。当前只是迁移与跨场景公共命令的首批实现，完整任务进度见[实施记录](游戏模型对齐实施记录.md)。

新增内容按以下顺序维护：

1. 已有机制能够表达时，修改 manifest 的 `models` 数据集，组合操作、变量和触发条件；结构遵守 `contracts/game-models.schema.json`，再运行结构及绑定校验。
2. 新机制在现有 `rules/`、`simulation/` 或 `evaluation/` 对应模块实现，覆盖实际状态变化和触发顺序。
3. 在机制资料中补充 `id`、规则说明、实现位置、操作名称和已知边界，并添加验证行为的测试。

JSON 直接成为核心输入；不新增兼容层，不通过逐实体审核名单开通执行能力。`verification` 只记录核对证据，不能当作逐实体执行许可。检索到某个描述或源码，只是获得参考资料。

怪物 119 个声明已进入同一 models 数据集，仍全部待语义复核。离线迁移工具为 `tools/analysis/compile_monsters.py`；运行时不导入提取器，也不解释 C# 源码。事件当前只有五个声明，战斗入口和条件奖励只构成观察边界，不能提前取得或把后续结果算已知。

选牌的作用与后续效果由 `models.selections` 声明，`rules.selections` 和 `evaluation.selections` 直接消费。Bridge 记录实际选择 API、回调、来源和完成令牌；当前四个合同覆盖休息升级、蓝宝石种子升级、禅意织者单张/双张删除后付款。未知来源、转化和附魔的效果仍未完成，不能由屏幕名或提示词补齐。

默认牌组与战斗批次不再从描述提供缺失效果的数值分数；没有动作规则时保留未知，并阻止以这个不完整比较自动决策。商店药水和储备代理读取同一效果声明，策略区间只在配置中定义。描述资料只作参考展示，所有估值及触发次数保持未知；不会为缺失规则补数值。

Cook 选择合同按实际回调顺序移除两张牌再增加 5 点最大生命，取消跳过；Smith 的休息预测和选牌预测共用 JSON 后续合同。预算截断、未知候选或钩子缺口不提供完整收益分。完整状态、其他休息选项和转化/附魔仍待补齐。
