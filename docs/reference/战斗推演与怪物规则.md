# 战斗推演与怪物规则

## 本次修复

首回合没有有效出牌候选的原因是遗物资料导出增加了 `pool`／`pools` 分类字段。兼容校验现在先比较完整指纹；仅当去掉这两个新增遗物字段后的整份资料精确等于旧指纹，才接受旧格式。效果文本、动态数值和其它字段仍参加校验，游戏版本与程序集校验保持有效。不改写已审核指纹，也不把所有资料变化当作无害。

默认后续推演使用本地怪物行动图，取消自动重复当前攻击的假设。调用者仍可提供明确的攻击场景用于离线比较，但报告会区分人工场景与实际行为规则。旧抽牌概率单元测试中的虚拟怪物改为显式场景，不赋予它虚构的游戏行为。

## 模块边界

- `rules/monsters.py`：怪物招式识别、限制性数值与条件解释、行动图转移、随机权重及重复限制、怪物回合效果、覆盖审计。
- `decision/contracts.py`：不可变怪物状态，包含最大生命、虚弱持续时间、当前招式、已知历史与可见实例字段。
- `planning/lookahead.py`：玩家候选出牌、怪物回合、下回合资源重置与抽牌分支，按预算执行有限回合搜索。
- `telemetry/decisions.py`：向 AI 数据包加入推演结果；怪物行动记录每方案最多发送 8 条，完整记录仍保存在本地。
- `agent/context.py`：按推演中实际出现的实体补充生成牌的百科，不发送整份百科。
- `combat-forecast.js`：普通视图中的预计失血、敌人剩余生命、怪物换招、生成牌去向及覆盖说明。

修改模块版本和行为资料都会使战斗分析缓存失效。百科更新仍沿用现有本地导出入口；游戏程序集不匹配时拒绝执行旧怪物规则。

## 已接入的规则结构

所有本地怪物条目使用相同适配器，不通过少量怪物 ID 的白名单判断行为。适配器解析明确的攻击、状态牌生成、格挡、自身力量和给予玩家虚弱／脆弱。数值来自当前进阶对应的本地表达式；可见攻击用于核对当前招式。攻击意图与执行方法的数值、次数必须一致。

支持确定性换招、按顺序的条件分支、随机权重、禁止连续重复、有限重复、只使用一次和冷却限制。需要过去招式历史而当前历史不足时停止推演。首回合可以依据当前招式建立已知历史；状态字段始终使用游戏可见实例值，缺失时不根据声明初值猜测（入场钩子可能已经改变它们），不读取隐藏 RNG 或预先选好的未来招式。

生命阈值使用出牌后的怪物生命，并保留 C# 整数除法语义；玩家击杀的怪物不再攻击或塞牌。生成牌记录具体卡牌 ID、数量与牌堆，进入下一次抽牌与洗牌组成。黏液的抽一张并消耗效果已核对本地 `Slimed.cs`，复用抽牌和消耗原语。

敌人回合产生的格挡保留到下一玩家回合；虚弱持续时间及新施加给玩家的脆弱／虚弱分别处理，避免新减益在同一次转换里提前少算一回合。

## 覆盖边界

这不是全部怪物机制已验证的承诺。复杂生成／召唤、其它能力钩子、特殊死亡／受击逻辑、未知状态表达式、招式无法唯一识别、缺失历史、带条件的行动执行、不同的攻击执行顺序或预算不足，都保留为未覆盖项。不会把这些效果按零伤害处理，也不会自动转为“重复当前招式”。有特殊行动交互未建模时，当前出牌计算也会明确阻止，交给 AI 结合资料判断。

后续模块新增机制时，应新增受限操作和对应测试，而不是执行资料中的任意 C#／Python。现有怪物条目不需要重建一套查询库。

分支覆盖率仅描述当前窗口内已计算的概率质量；条件生存／完成比例不等于整场战斗胜率。搜索仍有节点、抽牌分支、深度和时间预算，不声称全局最优。

## 验证

单元测试覆盖进阶 9 的数值变化、状态牌去向、击杀后停止行动、敌方格挡、条件生命阈值、随机概率、状态字段更新、力量、减益持续时间、历史不足、版本失配、未知效果、限制性解释器，以及 AI 数据包和前端投影。生成牌的抽牌／消耗链路与两回合推演另有本地知识测试。

可移植怪物图测试不依赖游戏资产，纳入 CI；标记 `local_knowledge` 的测试需要本机导出的百科，纳入完整本机回归。测试不执行真实游戏动作。

当前实战首回合快照的只读核对：有效候选从空方案恢复为 5 个；遗物兼容警告消除；中型树叶史莱姆塞入 2 张黏液后切换攻击，小型树叶史莱姆按不重复规则换招。此核对验证了读取和计算接入，不代替多次真实回合的预测与实测校准。

2026-10-12 最终验证：完整 Python 回归 377 项通过，前端 34 项通过，可移植怪物规则检查 17 项通过。已部署并刷新当前首回合的分析归档，确认 AI 数据包包含后续推演，观察台显示两回合失血预测与怪物换招。游戏和 Agent 保持暂停，未执行出牌。
