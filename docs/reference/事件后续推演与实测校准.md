# 事件后续推演与实测校准

## 当前实现

事件资料来自本机游戏，覆盖所有事件的查询与源码参考。机制定义在 manifest 的 models JSON；`rules.flows` 和公共命令执行声明，`evaluation/event_sequences.py` 估值；百科与源码资料用于参考。

当前五个流程为深渊浴场、巨型花朵、真理石板、灯笼钥匙、茂密植被；战斗入口与条件奖励保持观察边界。原运行时终结资源源码识别已删除，提取器只供离线审计。另有蓝宝石种子和禅意织者的已观察选牌后续合同，不代表这两个事件已完成全流程建模。未声明效果不赋零分。

巨型花朵读取本次深入次数，比较现在领取金币与继续深入；花粉核心价值尚未完成机制建模，该分支保留未知，因此不会宣称完整最优。

真理石板读取当前解读次数与实际费用。费用按 3、6、12、24、当前上限减 1 变化；随机升级按当前可升级实体牌池均匀分支，最后阶段升级全部可升级牌。每次升级后更新牌池，每次失去上限后更新生命截断和资源紧迫度。未知卡牌价值、缺失实体、源码变化、搜索超限或相关遗物钩子会使比较不完整。

通用状态图支持明确给出的随机概率和重复路径。不是任意 C# 执行器；动态奖励池、特殊遗物、附魔、事件战斗等需要补充现有机制实现。所有事件推演仅供判断，不能单独授权自动执行。

## 实时与历史观察

观察台显示本次选择收益、后续收益、风险扣分、模型内致死概率、本次生命／上限／金币变化期望，以及各个分支结果和后续选项。完整树存于本地决策记录；AI 只收到当前分支和后续摘要，避免重复树挤占上下文。

当前变量和阶段字段必须来自游戏。界面提供读取核对面板；源码默认值不能代替未观测的阶段。资料与运行游戏使用版本及程序集 SHA 核对。百科更新后相关决策缓存失效；游戏更新需要同步核对现有机制代码，不存在逐实体适配审批。

## 实测与校准

Agent 完成一个事件动作后，自动核对同一会话、同一局、同一楼层、相同游戏版本与 SHA、递增状态版本，再记录预测和实测的资源变化。未结算动作、跨会话和跨局结果不自动关联。观察台的结果证据页显示差值。随机分支同时核对结果是否属于模型内的可能值，不能把单次偏离期望当作模型错误。

事件观察保存在 `data/calibration/observations`，完整决策及地图节点记录仍走现有按日期分局归档。也可以通过现有校准接口选取 `event_sequence` 候选并记录 action 级结果。运行以下命令生成本地统计：

```powershell
.runtime/conda/python.exe src/python/tools/analysis/audit_event_outcomes.py
```

输出为 `data/knowledge/coverage/event-outcomes.json`，列出生命、上限、金币的样本数量、平均偏差与平均绝对误差，并按游戏 SHA、事件和模型版本分组。无样本时明确显示等待实测；不会用零误差冒充验证通过。未能计算预测值的事件也会记录实际结果，但不会进入数值误差样本。

资源预测校验与策略权重校准分开进行。先核对执行记录、规则和钩子，再结合现有实战校准流程比较权重配置；单次结果既不能证明未选项收益，也不能证明赢率提高。此次不自动修改权重。

## 本次验证边界

离线测试覆盖重复阶段、费用与生命截断、随机升级池、概率、致死分支、未知后续、版本变化、上下文摘要和实测关联。游戏当前未连接，实际事件字段与选择后的转移还需要后续实战验证。运行状态保持暂停，没有为收集样本而自动开始游戏。
