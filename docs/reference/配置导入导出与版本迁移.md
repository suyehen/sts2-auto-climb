# 配置导入导出与版本迁移

在工作台「Agent 管理 → 配置备份与迁移」操作。范围仅为业务配置，不包含对局记录、决策快照、地图、实战校准样本或运行日志；百科与图片仍保留在本地，不打包进配置文件。

## 导出范围

- **标准配置**（默认）：当前模型后端列表、默认后端、决策评分与搜索参数、自动执行规则、跨回合遗物参数、人类／工程展示偏好。JSON 可直接查看，不包含 API 密钥。
- **完整配置**：上述内容和各后端当前生效的 API 密钥，整个文件使用备份密码加密。AES-256-GCM 校验文件完整性，Scrypt 派生加密密钥，每次生成随机盐和随机数。密码至少 8 个字符，不写入配置或日志。

这里的「标准」是当前配置去掉密钥，并非恢复出厂值。完整配置可在另一台电脑导入；不导出本机 Codex 登录凭据，也不搬运其登录会话。目标电脑需自行登录。环境变量优先于本地保存的密钥，如目标电脑已设置相关环境变量，它仍然优先。

## 导入与恢复

1. 选择 JSON；完整配置需填写备份密码。
2. 读取并预览默认后端、后端列表、参数变化和包含的密钥数量。预览不显示密钥，不改配置。
3. 点击「应用配置并暂停 Agent」。服务先校验，暂停 Agent 后才写入配置，并保留旧配置与本机加密密钥的备份。
4. 在「导入与升级前的本地备份」可恢复。恢复前也创建备份；恢复后保持暂停。

标准导入只有在后端 ID、类型、地址和密钥环境变量名均未改变时才保留原有密钥的使用权限，避免把旧服务密钥发送到新地址。变化的后端需要重新填写密钥，或通过完整配置导入。配置文件中的本机 Codex 可执行路径重置为 `codex`，适应目标电脑。

## 版本与保存位置

当前导出格式为 `autoslay-config`、`schema_version: 2`。支持旧的裸 `version: 1` 后端配置和第 1 版导出信封，缺少的新字段使用当前默认值。未知未来格式、未知参数、不合法预算和试图解除固定自动执行校验的配置会被拒绝。此兼容范围不代表任意历史策略语义版本均可自动转换。

- 仓库默认参数：`config/decision/*.default.json`。
- 用户配置及策略覆盖：`.runtime/local/agent/profiles.json`，统一原子替换；不覆盖仓库默认参数。
- 本机 API 密钥：`.runtime/local/agent/credentials.dpapi.json`，Windows 用户绑定加密。
- 导入与升级备份：`.runtime/local/agent/backups/`。备份仅在本机恢复；跨电脑使用完整配置导出。

后续新增字段应提高配置格式版本，在迁移函数中明确补默认值或转换，并为旧文件保留测试。策略语义发生变化时需增加专门的转换规则，不能仅改版本号接受旧值。

## GitHub 发布

公开分享优先使用标准配置。完整加密配置用于个人迁移，不提交到仓库。`.gitignore` 已排除运行目录、默认命名的导出文件、密钥文件和对局／索引／实战样本目录；手动改名的导出文件仍需在提交前检查。

当前工程还有本地游戏导出的百科、图片和回放夹具。它们保留在电脑本地，并通过 Git 忽略规则排除；配置导出不会自动打包它们。公开仓库的范围见 [GitHub 发布说明](GitHub发布说明.md)。
