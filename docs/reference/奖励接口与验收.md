# 基础奖励接口（0.3.0）

适配游戏 v0.111.0。基础奖励代码随 0.4.0 合并部署，金币、药水、打开卡牌奖励、选卡及继续的真实验收已通过。遗物领取和跳过/重选等分支尚未实测。

## 读取与决策

`get_state` 增加 `state.reward_screen`，包含当前界面实例 ID、类型、奖励列表、可见候选卡、替代选项及决策就绪状态。金币含金额，遗物/药水含实体 ID，卡牌含标题、规则描述、费用、升级信息。仅在打开卡牌奖励界面后暴露其候选卡。

奖励界面的 `phase=rewards`；卡牌选择界面的 `phase=card_reward_selection`。工具仍是 `act`，根据新快照中的 `state.legal_actions` 提交单个动作，目标为 null。每次由 Codex 作决策。

| 动作类型 | 行为 | 完成条件 |
|---|---|---|
| claim_reward | 领取金币、遗物或药水；打开普通卡牌奖励 | 游戏领取任务完成且队列稳定，或卡牌选择已打开 |
| choose_reward_card | 选择当前可见的一张卡 | 正常入牌流程完成；多选机制下等待新的选择回合 |
| reward_alternative | 使用界面提供的跳过、重选等替代选项 | 游戏任务完成或新选择回合已经出现 |
| proceed_rewards | 继续；界面为跳过时放弃余下奖励 | 奖励界面切换且队列稳定；出现教程弹窗则要求人工处理 |

打开卡牌奖励的 completed 表示“打开成功”，不表示已经拿到卡。必须重读状态，由 Codex 再提交选择动作。跳过卡牌后，该卡牌奖励可能仍留在奖励列表，这是游戏正常行为；要离开仍需单独选择继续。

## 执行与限制

通过原生 `NRewardButton.GetReward` 异步领取流程和原有选牌/按钮信号执行，不直接修改金币、牌组或奖励台账。部分 UI 成员是私有成员，适配代码集中于 `RewardCommands.cs`，并由固定游戏版本检查保护；升级游戏后需重新验证。

派发仍要求当前局、会话、最新状态版本、合法动作、单人模式和非暂停。必须是当前实际活动界面，检查教程/模态弹窗与队列状态，不穿透地图、检视卡牌等覆盖界面。领取任务等待选牌期间，允许完成后续选择，不允许额外领取其他奖励。

未知或复杂界面返回 needs_user_input 并保留执行槽。请求超时只查询原 ID，不替换为新请求。进程重启会更换会话 ID，去重不跨重启持久化。

当前未覆盖链接奖励、删牌/特殊奖励、战斗内子选择、药水使用，以及地图、商店、休息和事件。药水奖励领取不等于药水使用；背包满时正常游戏可能拒绝领取。遗物可能触发尚不支持的子界面，需要实测和逐项扩充。

## 检查与游戏内验收

已通过：零警告零错误构建；18 项 C# 检查，包括去重、打开奖励后释放指令、等待真实入牌、重选/多选令牌变化、跳过、继续时的教程弹窗/超时以及任务失败优先处理；9 项 Python/MCP 回归测试。

2026-10-08 经真实 MCP STDIO 验证：读取 13 金币、迅捷药水和普通卡牌奖励；金币 99→112，重复同一请求返回原回执且没有再次加钱；药水进入空药水栏。打开卡牌奖励后读取余烬、血墙、双重打击及跳过选项；初始防误点期间卡牌不可选，之后合法卡牌动作自动出现。Codex 选择双重打击，牌组 11→12，奖励列表清空。最后继续到 NMapScreen，ready=false、busy=false、合法动作为空，并暂停控制。

汇总证据：`.runtime/logs/menu-reward-live-verification.json`；每步完整记录：`reward-gold-completed.json`、`reward-gold-duplicate.json`、`reward-potion-completed.json`、`reward-card-opened.json`、`reward-card-chosen.json`、`reward-proceed-completed.json`。0.4.0 总计 23 项 C# 与 9 项 Python/MCP 检查通过；本次未实测遗物、跳过/重选/多选和复杂弹窗分支。

真实界面验收步骤：

1. 正常退出游戏后部署新版，重启确认 bridge_version=0.3.0、control_mode=paused。
2. 恢复单人进度，核对真实奖励列表和金币；若存档回到战斗，先通过新版战斗接口完成战斗。
3. 启用控制，领取金币，核对金额、移除奖励和完全相同请求的重复提交。
4. 打开卡牌奖励，核对候选卡与替代选项；确认打开动作已完成且新选择可提交。
5. Codex 阅读卡牌描述和当前牌组，决定选卡或跳过，核对牌组变化与正常界面关闭。
6. 单独继续至下一界面，确认地图等未支持界面不提供可执行动作，暂停控制。

每个动作前保存请求 ID 与前状态，结果包含回执和后状态。验收证据统一保存在 `.runtime/logs/`。
