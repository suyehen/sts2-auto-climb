# 卡牌、遗物和药水的统一机制模型

2026-10-19 更新：实体声明从 Python 注册表迁入 manifest 的 `models` JSON，公共操作仍由现有 Python 核心执行。已补五个事件和 119 个怪物的结构迁移，但全量实体语义及交互仍未完成；详细证据和剩余任务见[实施记录](游戏模型对齐实施记录.md)。本文件后续的旧扩展记录保留历史身份。

## 唯一执行路径

`decision.normalize` 读取实际状态，`rules.registry.KnowledgeRules` 绑定数值，`simulation.engine.CombatSimulator` 按顺序结算。战斗批次、策略搜索和前瞻直接使用同一个 `KnowledgeRules`，没有角色别名类或场景兼容类。

实体组合定义在 `data/knowledge/models/game-0.111.0.json` 中。`rules/model_store.py` 校验后构造 `EntityMechanics`、`Trigger`、`EffectSpec`；`ENTITY_MECHANICS` 仅为该数据集的只读视图。旧实体 Python 字典和卡牌/药水的文案数值解释均已删除。没有人工晋级或兼容状态检查。

已有操作能表达新内容时，修改这份 JSON 的操作、变量和触发条件，运行 `tools/analysis/validate_models.py`。出现新机制时，先补充现有执行代码，再更新[机制大全](机制大全.md)对应的机器可检索条目和行为测试。不可另建实体适配器。

## 已移除的旧架构

- `knowledge_base/rulebook.py`、外部 `rules/rulebook.json` 与 `effect-program` 编译解释器。
- 规则生成、审核晋级、指纹重绑与格式迁移工具。
- 实体级 `verified_adapter`、`pending_review` 和 `compatible` 执行许可。
- 独立事件适配模块；其机制已合入 `evaluation/event_sequences.py`。
- 附魔的逐卡牌兼容名单；共同使用规则模块的机制判断。

源码库存和描述分析继续用于参考展示、审计与覆盖报告。描述资料标为 reference_only，不能提供数值估值或触发次数，也不能生成或批准执行代码。未知机制不会因为描述可以解析而自动变成可模拟机制。

## 覆盖口径

本机百科仍收录 596 张卡牌、299 件遗物和 66 种药水。JSON 中迁移了原有 311 个条目，另外补充会员卡的价格修正，共 224 张卡牌、39 种药水、49 件遗物。311 个迁移条目仍标记待语义核对；这个数量不代表完整效果或交互验证覆盖。

其余实体仍可能缺少机制或组合定义。未知能力、修饰、分支和随机结果继续明确报告缺口；抽牌或新生成手牌的真实实例需要再次观察。移除兼容层不等于完成全量模拟。

桥接保留状态读取和传输，全局游戏版本及程序集检查保留以防旧机制用于新游戏；两者不定义另一套效果，也不审批单个实体。自动执行的证明条件仍独立于机制定义存在，不会把未建模效果当成已知。

当前覆盖可通过 `tools/analysis/audit_mechanisms.py --output <路径>` 重新生成，报告分别列出基础数据、声明、语义核对和交互验证。源码清单仍有模型类别缺失，不能把当前报告分母当成游戏全部模型总量。

## 本轮机制扩展

持续能力、X 费用、多段攻击修饰、人工制品、防御反伤、灵魂与小刀生成、持有诅咒、临时降力量、主动洗牌和遗物阶段数值已进入现有模拟器。基础评分、批次与前瞻共用伤害原语；桥接补充公开战斗历史与持续时间跳过标记。

当前百科范围仍有 649 个卡牌/遗物/药水缺少原生定义（另有未进百科的遗物 ID 待 ModelDb 对照），主要涉及充能球、集中、奥斯提进阶联动、铸造、重放、随机出牌、选牌移牌、费用变化和更多持续触发机制。已定义实体的全部交互也仍需逐项验证，不能将定义数量视为全量完成。

基础奥斯提机制已补入 `CombatState` 与共同伤害结算：召唤、治疗、独立攻击、代受攻击和溢出、钙化、骨笛及命匣的阶段召唤。桥接公开实际宠物状态；宠物存在与生命值不会由卡牌描述推断。

永冻的每战斗一次触发已改为读取实际使用标志并进入通用计数器；不再仅保存一个未参与结算的被动标记。灰烬之灵与噬魂分别接入出牌前和完整出牌后的阶段。

临时力量与敏捷按实际来源和应用顺序到期，人工制品能阻止属性扣回；铺垫打击不会被归入肌肉药水。熔融之拳追加易伤同样经过人工制品，最大生命下降会结算不可格挡伤害、剩余生命钳制及资源账本。
