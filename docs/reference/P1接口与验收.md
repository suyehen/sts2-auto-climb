# P1 基础战斗接口与验收

当前代码版本：0.2.0；适配游戏：v0.111.0。

## 本次实现范围

实现单人正常战斗中的合法出牌、目标选择和结束回合。出牌调用游戏的 PlayCardAction，结束回合调用 EndPlayerTurnAction，经正常 ActionQueueSynchronizer 入队。费用、伤害、遗物触发和回合结算均由游戏执行。

模组每次启动控制模式为 paused。启用 auto 本身不执行任何游戏动作；每个动作由 Codex 决定并单独提交。药水、复杂选牌和战斗外界面尚未实现。

## 工具与本地接口

| MCP 工具 | HTTP | 行为 |
|---|---|---|
| get_state | GET /state | 返回快照，顶层 ready 表示当前是否可提交新动作 |
| act | POST /act | 提交一个动作，随后有界查询同一请求的结果 |
| get_action_status | GET /action-status?request_id=... | 查询结果，不重复提交 |
| set_control_mode | POST /control | 设置 auto / paused |

合法动作位于 `state.legal_actions`，包含 action_id、card_instance_id、allowed_target_ids 和 allows_no_target。当前局 ID 位于 `state.run_id`；会话 ID 和状态版本位于快照顶层。无目标卡牌使用 target_id=null，不要为防御强行指定玩家目标。

只在最新快照 ready=true 时提交。数据读取失败、敌人回合、队列未空、拖拽出牌、模态弹窗、覆盖界面或手牌选择模式下，不允许新动作。请求进入主线程后刷新状态，再次检查会话、局 ID、状态版本、合法动作和目标。

## 请求结果

- received / executing：仍在排队或结算，应查询相同 request_id。
- completed：动作队列结束，已到达下一正常玩家决策点或战斗结束。
- rejected：未派发，例如旧状态、非法目标、暂停或忙碌。
- failed：发生异常或游戏取消动作，可能已经产生效果；必须重新观察。
- needs_user_input：当前动作在等待尚未支持的子选择，需要人工完成后继续查询。
- unknown：本进程没有该请求记录，不能据此断定没有执行。

dispatched=true 表示已经进入派发尝试，不等于一定产生预期效果。响应中可包含 snapshot；读取新状态仍是下一步决策的依据。

同一 request_id 与同一参数返回现有结果；更改参数则拒绝。被拒绝的 ID 也保留。单进程最多保留 4096 个记录，达到上限拒绝新请求，不静默清除去重信息。未派发请求超过 10 秒失效。进程重启后记录不保留，session_epoch 改变；不保证跨崩溃恰好执行一次。

act 最多等待约 25 秒，超时后不重新 POST，只查询原 ID。若状态仍不明确，停止新动作。子选择期间保留忙碌状态，人工处理后自动继续观察，不擅自放行其他动作。

## 已完成的验证

- C# 编译零警告、零错误。
- C# 命令台账 9 项检查：暂停、并发重复、忙碌、ID 冲突、派发前暂停、派发标记、完成后重复、释放执行槽、未知结果。
- Python/MCP 9 项测试：真实 STDIO 调用、响应丢失后仅查询、未知结果不重发、子选择返回、旧版接口提示和参数约束。

另已完成真实游戏验收：旧状态请求拒绝且资源未变；痛击扣费、伤害与易伤正确；完全相同请求返回旧回执且未再次产生效果；打击正确造成易伤伤害；无目标防御正确增加格挡；结束回合等待下一玩家回合；击杀后移除敌人与合法目标；胜利后 ready=false、busy=false、合法动作为空。Codex 在第 4 回合完成该战斗，最终血量 57/80，并暂停控制。

证据汇总位于 `.runtime/logs/p1-live-verification.json`。此次使用真实 MCP STDIO 客户端逐步调用工具；`execute_decision.py` 每次只执行传入的明确动作，调用前读取最新状态和检查合法性，派发前保存请求 ID。它不替 Codex 决策，也不自动循环游玩。

## 游戏内验收步骤

1. 关闭游戏后部署新版 DLL 与清单，再启动并恢复单人战斗。
2. 先读取状态，确认 bridge_version=0.2.0、control_mode=paused。
3. 启用 auto，重读状态，确认 ready 与合法动作合理。
4. 用旧 state_version 提交负向测试，检查 rejected 且游戏数据未改变。
5. 选择一张打击及合法敌人，由 Codex 提交一次出牌；核对能量、手牌、伤害和台账。
6. 使用完全相同 request_id 重复查询或提交，确认没有重复出牌。
7. 按新状态继续决策，测试结束回合后返回下一回合的状态。
8. 遇到未支持的子选择停止自动游玩；记录实际机制，再逐步扩充接口。

新版 0.2.0 已部署并完成上述基本战斗验收。药水、复杂子选择与战斗外操作仍待实现；这次基础牌组战斗不能代表所有角色、卡牌、遗物和敌人机制均已覆盖。
