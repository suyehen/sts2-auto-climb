# 全局动作目录与对象能力记录

实现日期：2026-10-15。

## 1. 唯一全局定义

`data/knowledge/rules/actions.json` 是当前桥接 42 种命令的全量目录，清单键为 `actions`，协议为 `action-catalog/1.0`，目录版本为 `1.0.0`。

覆盖战斗、药水丢弃、奖励、菜单、地图、事件、通用选牌、战斗嵌套选牌、商店、休息、宝箱及生命周期操作。它不声称列举游戏内部全部方法，也不把怪物行动伪造成 agent 命令。

每个定义包含：

- `type` 和稳定 `definition_id`，例如 `play_card` 与 `ACTION.play_card`。
- `group`、来源类别 `source_kinds`、适用阶段 `phases`。
- 实体类别 `source_entity_categories` 和对应桥接源码路径 `source_ref`。
- 目标规则 `target_rule`，与伤害范围分开。
- 前置条件、费用和效果的语义引用。
- 完成/观察边界、执行适配器、模拟支持类别。
- `agent_allowed`，集中定义退出等不参与普通 agent 决策的命令。

阶段、前置条件等描述不是另一份游戏权限引擎；动态条件仍由对应桥接适配器和游戏方法计算。语义引用如 `entity.card.effects` 由具体实体的效果档案解释，不表示已有一个可以执行任意表达式的规则解释器。

## 2. 跨语言引用

- C# `ActionCatalog.cs` 从同一 JSON 文件的嵌入资源读取定义，校验导出动作类型与目标形状。
- Python `autoslay.actions` 从知识仓库读取目录，参与固定知识快照；不维护第二份动作全集。
- 自动决策的行政动作排除集合、战斗命令集合、合法操作展开、模型回复验证与执行器目标验证引用该模块。
- 桥接 0.30.0 为快照增加 `state.action_catalog={version,sha256}`，为合法动作增加 `definition_id` 和 `source`。
- 新快照声明的目录与 Python 当前版本或指纹不一致时，报告记录差异，执行验证拒绝提交。
- 旧快照没有目录元数据时兼容读取；缺失动作类型的历史记录标记为 `LEGACY_ACTION_TYPE_MISSING`，不伪造其类型。

C# 每次实际执行仍运行已有游戏合法性检查。全局目录不直接授权任何实例操作，也不恢复此前删除的严格斩杀证明分支。

## 3. 对象能做什么

`entity_capabilities(entity_id)` 提供按实体查询的能力档案：

- 对应来源类别能提供的潜在命令，以及阶段和前置条件引用。
- 商店购买、奖励领取等 `contextual_commands`，与实体持有后的主动命令分开。
- 已声明不可打出规则对 `play_card` 的静态阻止标记。
- 已有卡牌/药水效果、遗物周期触发与规则引用。
- 已有机制范围记录中的触发钩子、读写状态和来源依据。
- 已有怪物招式和状态图引用、资料验证状态。
- 来源引用指纹、知识版本、未知能力可能性。

资料来自现有知识库，不通过解析描述猜测新能力，不将观测自动升级为已验证机制。`declared_rules` 仅表示有声明规则，不代表所有触发和交互完整覆盖。

例如开心小花返回周期能量规则，但没有伪造“主动激活开心小花”命令；怪物返回招式/状态图，命令列表为空。一个未知卡牌可以记录其卡牌类别的条件性 `play_card` 能力，同时明确效果未知；不能据此批准执行。

`entities_for_action(type)` 提供反查：动作的来源类别及知识库中潜在实体 ID。反查结果是能力范围，不是当前可用对象列表。

## 4. 此刻哪些对象可操作

`describe(snapshot)` 构建 `action-space/1.0` 观察记录：

| 字段 | 内容 |
|---|---|
| `catalog_version`、`catalog_sha256` | 本轮目录身份 |
| `source` | 会话、状态版本、本局身份 |
| `bindings` | 每个实时动作的目录引用、来源实体/实例、对象路径、合法目标、无目标权限、支持类别 |
| `objects` | 当前可见实例及其路径、原始可用性标志、关联实时动作 ID |
| `entities` | 本轮相关实体的能力和效果档案 |
| `issues` | 未注册类型、重复动作、定义/目标/目录不一致等诊断 |

来源绑定优先匹配实际手牌、药水或选择项的可见对象；没有具体对象时可使用桥接来源或明确上下文。解析不到的标记为 `unresolved`，不创造实体身份。

某个实例没有实时动作时记为 `not_exposed_currently`，不擅自解释成费用不足或没有能力。药水 `usable=false` 等游戏已导出的事实会保留，但没有依据时不补写禁用原因。

实体潜在能力、实时合法性和模拟覆盖程度始终分开。模拟搜索可以按模型推导假想合法动作；真正提交必须匹配当前游戏绑定和合法目标。

## 5. 如何查询

Python：

```python
from autoslay import actions

actions.catalog()
actions.definition('play_card')
actions.entity_capabilities('CARD.STRIKE_IRONCLAD')
actions.entity_capabilities('RELIC.HAPPY_FLOWER')
actions.entities_for_action('use_potion')
actions.describe(snapshot)
```

观察台只读接口，遵循已有 Host/Origin 和 `X-Autoslay-ReadOnly: 1` 检查：

```text
GET /api/actions
GET /api/actions?type=play_card
GET /api/actions?entity_id=RELIC.HAPPY_FLOWER
GET /api/actions/live
```

MCP 只读工具：`get_action_catalog`、`get_entity_capabilities`、`get_action_space`。

## 6. 如何留存

统一分析报告和本地执行决策报告包含 `action_space`，随现有决策归档保存，因而能还原“这一轮哪些对象有哪些动作和目标，以及引用了哪版知识”。模型紧凑包只带目录身份和诊断摘要，避免重复传输整套能力资料。

当前没有独立的“自动学习后写回能力规则”机制，也没有额外创建一套脱离原知识库的实体事实库。已知能力从现有版本化规则资料投影，实际观察存入决策归档。

## 7. 测试与加载

测试覆盖全量目录、效果/触发与命令分离、对象关联、反向查询、未知状态、目标校验、目录漂移、知识版本固定、只读 API 以及现有执行保护。C# 命令测试读取相同嵌入资源并验证类型和目标规则。

最终相关 Python 回归 309 项通过，排除此前已确认的 `test_malformed_model_reply_gets_one_fresh_bounded_correction[fixed]` 旧回复格式失败。桥接构建零警告、零错误，C# 命令测试通过，Python 与 C# 输出的目录 SHA256 一致。原有传输响应丢失、防重放等测试继续保留并通过。

新桥接需要重新构建并在游戏中重新加载，才能输出新增元数据。服务/MCP 也需加载新代码后才能提供新增工具。实现过程中不重启游戏、不提交真实动作、不自动将 DLL 安装到游戏目录。
