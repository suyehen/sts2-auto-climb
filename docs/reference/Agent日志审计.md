# Agent 日志审计

第一阶段覆盖本轮执行链、本地策略、模型调用、传输重试、决策校验与纠正、动作提交与回执、暂停、后端切换和中断动作恢复。新增事件复用 `data/runs` 的对局归档与现有历史时间线，不改变游戏操作授权或重试规则。

## 查看

重启 Agent 服务和观察台服务后，新的执行记录会显示在「历史回顾」的决策组中。点击审计事件可查看中文事件含义、处理状态、决策后端、模型、动作与目标、尝试序号、耗时、token 用量和关联编号。旧日志不会补造新增字段。

动作、目标、后端同时展示名称和原始 ID。动作与目标名称按事件发生时的公开状态捕获，不依赖后续百科版本；状态没有提供名称时明确显示「未知／未记录」。地图选择会说明房间类型和坐标，卡牌、药水、奖励、休息处及商品选择尽量保留具体名称。

「Agent 管理」展示审计健康状态：最近成功写入时间由状态接口提供，页面显示待补写数量和累计失败次数。归档失败时沿用现有 `.pending` 补写机制，由归档监视器恢复；日志故障不会触发游戏动作重试，也不会阻止暂停。

## 关联与记录边界

- `trace_id`：一轮决策处理链，将分析、模型请求、校验、动作和结束事件串联起来。
- `analysis_id`：候选分析编号；缓存复用时可能出现在不同执行链中。
- `plan_request_id`：一轮模型决策请求，包含首次回答和有限校验纠正。
- `validation_attempt`：首次决策或纠正决策；`attempt`：该次模型调用内部的传输尝试。
- `request_id`：本地执行或游戏动作请求编号，供恢复和回执定位。

模型传输「已返回」不等于计划通过校验，动作完成回执也不证明战略收益或效果已被观察。每次传输尝试的用量与整次模型调用汇总是不同层级，分析时不能重复相加。Codex CLI 当前未提供 token 用量，保持未记录，不填零。

新增审计不保存 API 密钥、请求头、服务地址、原始模型响应或内部思维链。通过校验的结构化动作和简短决策理由可保留；非法响应只记录校验字段位置及错误类型。

## 本机文件

`.runtime/logs/agent/audit/events` 保存逐事件审计元数据和发生时的名称；`health.json` 保存写入健康信息。完整公开状态交由对局归档去重存储，避免每次模型尝试都增加一份完整快照。没有有效对局身份的服务控制事件只保存在本机审计目录。

这一阶段还没有增加自动异常规则、审计专用筛选页、容量清理或完整服务控制事件浏览器。现有执行审计工具仍用于对局执行证据检查；后续可基于执行链扩展规则与筛选。
