# 本地战斗决策率与 Agent 异常修复

审计对象：`a3736dc369c8f45cb651c0334b42b410`，从 2026-10-11 开始的同一存档。截至原日志末尾到第 19 层、第二幕战斗回合 2，Agent 已暂停；没有游戏胜负终局。

## 原始比例与拒绝原因

原归档有 124 条战斗分析，其中记录了选择的有 107 次：本地 11 次、AI 96 次。本地率为 **10.3%**。不能把重试、仅分析记录或同一计划的多张出牌混入选择次数。

旧逻辑主要处理唯一动作、强制结束回合、必须全选、少数经过认证的斩杀。普通回合没有可独立接管的本地策略。`score_review` 的分差只用于诊断，不能作为最优证明。原日志常见阻碍可重叠，包括未来资源上界未认证、能力需要复核、锋利痛击缺少修饰认证、药水取舍、芒果被当成未知战斗遗物、X 费牌和未认证怪物阶段。

## 实现的修复

1. 保留分析前的严格证明快路径，增加分析后的本地分流。本地局部策略只有在搜索未截断、动作与当前合法目录覆盖吻合、没有未建模交互、可见能力与牌面修饰已核对时，才从已覆盖的动作前缀中选择。优先当前可见的结束战斗、减少预计失血和战斗收益；只执行首步，再观察并重新计算。
2. 抽牌以新的观察为边界，不安排未见手牌。不可打出、过于昂贵的牌不再仅因缺少适配器就阻断所有当前动作；能够改变资源并使这些牌可用的情况仍需复核。动作来源哈希和执行前的两次新状态校验保留。
3. 局部策略明确标记 `decision_basis=bounded_combat_strategy`、`optimality_proven=false`，界面和归档不把它称为整局最优证明。此规则可通过自治策略的 `enabled_rules` 中的 `bounded_combat_search` 单独关闭；原严格证明规则独立保留。
4. 不自动消耗药水。若药水在已建模候选中可降低预计失血或帮助斩杀，交给 AI 处理资源取舍，而非盲目保留药水。
5. 核对本地游戏源码：芒果只有 `AfterObtained` 增加最大生命，没有战斗钩子。战斗使用已观测的最大生命，不再把它作为未知交互整场阻断。锋利对痛击的可见伤害加成有单独认证，不扩展到未经核对的附魔或附着效果。
6. 本地执行器因新状态变化或其他执行器占用而拒绝提交时，重新观察；不把这种提交前的短暂竞争当成 Agent 致命错误。不重试任何已经提交的游戏动作。

## 最后一次异常

最后一条错误为 `MODEL_INVALID_DECISION`，发生在第 19 层、回合 2 的 `waiting_model`，请求编号 `35208c956b2a447b83c693e5b97eccb4`。该请求没有成功提交游戏动作的记录。旧日志没有保存具体校验字段或原始模型回复，因此不能断言究竟是字段缺失、类型错误、长度越界还是 JSON 语法问题。

现在遇到 JSON／结构校验失败，会先确认原局面仍一致、尚未执行动作，再进行最多一次纠错请求。仍然失败就停止，新增诊断保存字段路径和校验类型。局面改变、暂停、切换后端时取消纠错；不执行被拒绝回复的任何部分，不记录原始模型内容或私有推理。已有非战斗多步回复纠错仍然保留。

## 验证和局限

离线回放重新分析归档的公开快照，不改写原始决策和历史计数，不调用在线模型，不发出游戏动作。新增本地机会不代表新轨迹的实测比例：改变首步会改变后续手牌、意图和决策次数。

剩余主要阻碍仍包括同族神官死亡与随从联动、偷窃草蜢逃脱和被偷卡归还、紧缠及其他未覆盖能力，以及当前前缀无法形成可用候选。这些情况继续交给 AI。最后一场偷窃草蜢战仍有这些阻碍，因此模型纠错的修复也独立必要。

本地开关已启用，旧本地配置已备份。后台只加载修复并保持 Agent 暂停，不继续本局；真实运行比例需后续游玩观测。
