# 机制覆盖与动态状态

本模块区分资料收录、可执行基础规则、计算结果和执行证明。百科完整不代表完整模拟；怪物的行为图目前用于查询和 AI 判断，不会自动成为计算器规则。

## 全量审计

执行 `.runtime/conda/python.exe src/python/tools/kb_admin/audit_mechanisms.py`，结果写入 `data/knowledge/coverage/mechanism-audit.json`。包含所有卡牌、药水、遗物、事件、怪物、意图及其状态。观察台 `/api/coverage` 每次读取当前资料与规则生成审计，不依赖旧导出。

当前 1151 个实体中，82 个有兼容基础适配器，879 个卡牌、药水或遗物尚需 AI 理解，190 个事件、怪物和意图为参考资料。适配器可在抽牌、未知交互等处停止，并不承诺支持实体全部效果。

## 单次决策报告

报告 `mechanism_audit` 同时进入 AI 数据包、观察台主页面/侧栏和历史记录。

- `exact`：已通过原有确定性执行证明，仅证明当前选择，不证明整场最优。
- `estimated`：存在有条件候选评分；仍需 AI 判断。
- `ai_required`：当前没有可用的候选估算或确定性证明。

`metric_scopes` 单独标注可见数据、本回合失血估算、伤害的有限模型范围、尚未支持的后续怪物分支和未校准胜率。未知不当作零。此模块只审计，不扩大执行授权。

## 动态状态

桥接 0.28.0 在游戏主线程读取怪物模型上的布尔和数值实例字段，包含自动属性的底层字段。只读字段，不执行属性 getter，不读取 RNG、抽牌顺序或复杂对象。字段读取失败单独标记。`combat_instance_id` 区分每场战斗。

Python 按当前游戏构建匹配本地行为资料，将字段与源码中的状态定义对应，并提供属性别名。例如青蛙骑士 `_hasBeetleCharged` 对应 `HasBeetleCharged`。缺失、不匹配或类型错误的字段都为未知，不能借源码初始化值补成 false/0，也不能把已公告的意图当作已执行行动。

跟踪范围为进程会话、对局、战斗实例、怪物实例。相同版本重复读取不重复产生变化；旧快照不回写状态。仅在连续两次快照都读取到字段时记录前后值。最多保留 128 个战斗范围；跨重连重新观测，不推断中间发生了什么。报告中已记录的变化随既有按日期/对局归档保存。

旧版桥接仍可提供可见数据，但没有战斗实例/额外字段，报告明确标为未跟踪或未知。升级后新读取的快照自动使用新版字段。

## 边界及后续扩展

这版不编译任意 C# 方法，也不新增通用多回合模拟。复杂分支、动态事件流程、未建模的能力交互仍交给 AI。源代码中的字段列表可能尚不涵盖复杂容器或继承属性，状态计数为“已登记字段中的未知数”，不等于完整状态覆盖率。

后续可以为审查过的机制逐项添加受限执行规则和独立测试，再接入现有模拟器；实时审计会据规则兼容性更新。完整游戏更新后先更新百科和行为资料，再核对规则指纹；旧构建的状态定义不能直接用于精确推演。
