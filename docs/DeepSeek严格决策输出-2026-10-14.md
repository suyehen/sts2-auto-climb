# DeepSeek 严格决策输出

已接入并实测 `deepseek-flash` 的原生严格工具调用。该接口只提交决策数据，游戏操作仍由本地执行器逐步校验后执行。

## 原生能力与限制

- 请求使用 `https://api.deepseek.com/beta/chat/completions`，只提供 `submit_decision` 一个函数，设置 `strict: true`。
- 每个对象的字段全部必填，禁止额外字段；当前请求的 `state_token` 使用单值枚举约束。
- DeepSeek 文档列出的严格模式暂不支持 `minLength`、`maxLength`、`minItems`、`maxItems`。长度、步数、合法动作、目标和状态有效性继续在本地校验。
- 传输 Schema 的目标为字符串，无目标用空字符串表示；收到后仅将该约定转换为内部 `null`，不修补其他错误字段。
- **思考模式不支持强制指定工具或 `tool_choice: required`**。首次实测指定工具名收到 HTTP 400，官方错误为思考模式不支持该 `tool_choice`。因此保留当前 `low` 推理，使用 `auto`，只接受唯一的 `submit_decision` 调用。关闭思考（`reasoning_effort: none`）时可强制指定该工具。

严格模式约束工具参数，不保证思考模式下每次回复必然包含工具调用，也不证明决策在游戏中合法或最优。

## 错误处理

- 只回复文本、工具名错误、多次工具调用等均不执行，确认游戏状态未变且 Agent 仍在运行后，最多纠正一次。
- JSON 损坏、缺少字段、非法类型、超长或空计划仍由已有本地校验拒绝并纠正一次。
- 仅当 HTTP 400 的结构化错误明确指出严格模式或工具选择能力不支持时，回退到 `json_object`，并记录回退事件。普通 400、Schema 构造错误、鉴权错误不自动降级。
- 输出截断继续使用原有的有限扩容重试。无论哪一种推理重试，都不重放游戏操作。
- 日志保留标准错误代码、校验信息和 token 计数，不保存原始回复或密钥。
- 前端高级设置可手动选回 JSON 模式。

## 验证

2026-10-14，使用当前已配置的官方 `deepseek-flash`、`reasoning_effort: low`，提交一次非游戏状态的合成奖励选择请求：

- 严格工具调用成功，无兼容回退；
- 返回单步 `skip_reward`，无目标，状态标识匹配；
- 本地决策结构及预期动作校验通过；
- token：输入 1052，输出 137，其中推理 12，总计 1189；
- 执行游戏操作数量：0。

一次合成验证不能作为整局格式成功率或游戏胜率的测量。完整游戏上下文中的效果需后续对局统计。

回归：115 项 Python 测试、69 项前端测试通过，`git diff --check` 通过。覆盖严格请求格式、目标转换、错误工具、超长和空计划、显式兼容回退、重复失败、暂停及状态变化等情形。

启用时备份原本地配置，只将 DeepSeek 输出模式改为 `deepseek_strict`，保留模型、推理设置、密钥和其他决策配置。通过服务管理器重载 Agent，保持暂停。

## 相关代码和验证命令

- `agent/contracts.py`：DeepSeek 兼容 Schema、提示和无目标值转换。
- `agent/providers.py`：严格工具请求、返回参数提取和有限兼容回退。
- `agent/runtime.py`：无工具回复的状态校验与一次纠错。
- `tools/analysis/probe_deepseek_strict.py`：仅发起合成模型请求，不接入游戏。会使用模型额度。

在仓库根目录运行：

```powershell
$env:PYTHONPATH='src/python/src'
.runtime/conda/python.exe -X utf8 src/python/tools/analysis/probe_deepseek_strict.py
```
