# 确定性决策模块

本次实现的是本地 Agent 在请求模型之前使用的确定性前置层。它不依赖模型 API、嵌入模型或向量检索，也不会启动游戏或自行解除暂停。完整的模型 API Agent 循环尚未接入；本模块通过常驻执行服务提供入口。

## 当前流程

状态读取 → 确定性规则检查 → 成立则执行一个动作并重新观察；否则返回 `ai_required` 或 `wait`。

统一分析接口 `/decision` 也先做检查。规则成立时不运行战斗搜索，并返回 `ai_required: false` 和完整证明。读取分析本身不会执行动作。规则不成立时继续生成已有数学模型报告，供 AI 决策。

`ai_required` 表示存在取舍或信息缺口；`wait` 表示暂停、断开、动画结算或暂无可用操作，不能直接当成模型决策请求。当前模块不替调用方请求模型。

## 已实现的规则

| 规则 | 自动处理 | 主要边界 |
|---|---|---|
| `forced_action` | 唯一可走地图节点、事件结束后的继续、奖励已全部领取后的继续 | 不自动跳过尚存在的奖励，不把菜单退出算作策略候选 |
| `forced_end_turn` | 唯一剩余回合内操作是结束回合 | 必须排除所有合法出牌、药水和特殊操作；不会推断下一回合威胁很小 |
| `mandatory_card_selection` | 必须选择全部候选且不能跳过，逐张选择后预览/确认 | 可选子集、可取消选择和带未知操作的界面交给 AI；不在嵌套父动作中猜测语义 |
| `certain_combat_finish` | 一张牌能确定结束战斗，且不存在相关长期收益取舍 | 检查全部手牌和卡组、药水、遗物、敌人死亡机制、隐藏能力、附魔与负面附着；未知则不自动执行 |
| `eliminate_certain_death` | 游戏明确标记其他选项致死，且仅剩一个源码核对过的安全退出 | 不靠描述中的扣血数字猜死亡；考虑先增加上限/回血再受伤和生命变化钩子 |

击杀规则能比较多个确定击杀动作的战斗结束结果，结果等价时按动作 ID 固定选择。燃烧之血的战后回血单独计入预测。

## 通用比较与扩展

`decision/outcomes.py` 提供等价、占优、被占优、存在取舍和未知五种比较结果。它要求结果确定、相关维度完整、后续状态相同；任一条件缺失都返回未知。比较不使用加权总分，也不把最高分当成必然最优。

第一版已经把等价比较用于确定击杀。**尚未对任意商店、事件或卡牌组合开放自动占优执行**：这些场景需要相应的完整效果适配器，不能把模拟器部分覆盖或百科文字直接当成证明。

新增场景的步骤：

1. 使用现有桥接获取其动作、目标、实际资源和机制信息。
2. 如现有规则已覆盖其语义，则直接适用；否则新增独立证明函数。
3. 若涉及实体行为，核对源码或可靠的机制证据，登记游戏版本、程序集指纹和来源。
4. 为证明函数提供全部持久结果维度及后续状态，使用通用比较模块。
5. 加入成功、反例、未知机制和版本变化测试，再在配置里启用。

证明函数不能接受调用者随意声明“完整”“无副作用”作为执行证据。`/autonomy` 执行时只接受请求 ID，证明由本地重新计算。

## 文件位置

- `src/python/src/autoslay/decision/deterministic.py`：规则入口、检查与证明。
- `src/python/src/autoslay/decision/outcomes.py`：独立的精确结果比较。
- `src/python/src/autoslay/decision/autonomy.py`：旧接口的兼容入口。
- `src/python/src/autoslay/execution/deterministic.py`：最新状态校验、一次动作执行、持久请求与恢复。
- `config/decision/autonomy.default.json`：总开关、启用规则与版本。
- `data/knowledge/rules/deterministic-certificates.json`：经过源码检查的证明范围，与全量百科分开。
- `src/python/tools/game/run_deterministic.py`：本地确定性短流程客户端。
- `src/python/tests/test_deterministic.py`：规则反例、执行去重和恢复测试。

全量百科仍然保留。证明范围较窄，表示“可省略 AI 的范围”，不表示游戏只认识这些实体。当前击杀死亡机制证书覆盖四种树叶/树枝史莱姆，遗物证书覆盖燃烧之血与轰鸣海螺；其他组合会明确返回检查缺口。周期遗物和卡组中尚未抽到的永久成长卡也会阻止立即击杀快捷执行。

版本或程序集指纹改变时停止使用原证书。百科自动更新不会自动批准旧证书；需要核对机制后更新证书。

## 接口与使用

在执行服务启动后，只读检查：

```powershell
.runtime/conda/python.exe -X utf8 src/python/tools/game/run_deterministic.py
```

显式执行确定性前缀（最多 12 个动作，遇到 AI 决策、暂停、断开或未结算立即返回）：

```powershell
.runtime/conda/python.exe -X utf8 src/python/tools/game/run_deterministic.py --execute --max-actions 12
```

该命令不启用自动模式。游戏必须已被用户或上层 Agent 授权切换为 `auto`。服务监控线程仍然只读取状态。

常驻服务新增认证 POST `/autonomy`：

- `{}`：检查当前状态，不执行。
- `{"execute": true, "request_id": "unique-operation-id"}`：重新获取状态、重新证明并执行一个动作。
- 同一 ID 再次请求只返回已保存结果；中断后不重发。
- 前一个请求未能确定结算时，新 ID 也会被阻止；仅通过动作状态查询恢复，`unknown` 不当成成功。

执行使用与已有动作计划相同的跨进程锁。提交前再次比较会话、运行 ID、状态版本和状态指纹；最后由桥接校验合法动作。每个动作后重新观察，不自动跨越抽牌、随机结果或选牌决策。

## 观察与存储

每个实际本地动作记录 `decision`、`local_choice` 和 `local_outcome`，以及已有动作提交/结果记录。它们进入原来的按日期、对局、幕和地图节点归档。

实时侧栏显示“本地确定性决策 · 未调用 AI”、规则、成立依据、检查缺口和执行信息。完整报告保留详细证据；对局统计区分已登记的 AI 选择与本地选择。它们不会伪装成模型校准样本。
