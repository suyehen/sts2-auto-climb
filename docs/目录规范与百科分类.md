# 目录规范与百科分类

## 当前源码布局

```text
launch/                         日常启动入口：CMD、PowerShell
scripts/build/                  PowerShell 构建、部署、回归测试
scripts/game/                   PowerShell 游戏重启入口
src/
  python/
    pyproject.toml              Python 包与依赖定义
    environment.yml             Anaconda 环境定义
    requirements.lock.txt       当前环境依赖锁定
    src/autoslay/               Python 核心包
      mcp/                      MCP 接入，独立于业务逻辑
    tests/                      Python 测试
    tools/
      runtime/                  本地服务、观察台启动、MCP 调用与后端探测
      game/                     游戏状态和动作工具
      analysis/                 计算、基准、评分校准工具
      knowledge/                百科、规则、游戏卡面维护工具
      archive/                  归档迁移和索引重建
      setup/                    环境安装工具
  csharp/
    bridge/                     游戏桥接项目
    observer/                   WPF 侧窗项目
    tests/CommandTests/         C# 回归检查项目
    tools/Inspector/            程序集检查项目
    global.json, NuGet.Config   C# 共用 SDK / NuGet 配置
  web/
    public/                     HTML、CSS、ES 模块
    tests/                      Node 原生测试
    package.json                前端模块声明和测试入口
contracts/                      跨语言协议 JSON Schema
config/                         语言无关的决策策略参数
data/knowledge/                 百科、规则、分类、游戏插画
data/runs/YYYY-MM-DD/            按日期存放的对局记录
docs/                           项目说明与验收文档
.runtime/                       环境、SDK、缓存、构建临时产物、本机配置及日志
```

Python 工具使用 snake_case，PowerShell 脚本采用 Verb-Noun 命名，C# 项目和类型保持 PascalCase。各语言测试与依赖定义放在所属语言项目中。JSON 按用途存放：策略属于 `config`，协议属于 `contracts`，游戏资料属于 `data/knowledge`，用户对局属于 `data/runs`；不能把所有 JSON 混在源码目录。

## 用户启动方式

- `launch/start_agent.cmd`：启动本地服务、侧窗和完整页面；Agent 默认暂停。
- `launch/start_observer.cmd`：打开实时侧窗。
- `launch/start_history.cmd`：使用系统默认浏览器打开完整页面。

三个入口都可以双击，不依赖调用时的工作目录。MCP 注册路径已同步到 `src/python/src/autoslay/mcp/server.py`，其他 Codex 设置保持原样。

## 百科分类与升级效果

卡牌、药水、遗物分别浏览。同时属于多个游戏池的遗物保留所有来源，可在各来源下检索。可按职业／来源、稀有度筛选；卡牌额外按攻击、技能、能力等类型筛选。职业筛选可以选择包含通用资料。事件、生成专用、任务、诅咒、状态、已弃用和测试资料保留独立类别，不冒充通用可获取资料。

分类优先使用游戏百科导出的 `pool` 字段。旧遗物导出遗漏此字段，因此 `classification.json` 根据本版本游戏遗物池定义补齐了 299 个遗物的归属，并记录来源与程序集指纹；游戏版本指纹变化后，旧分类不再套用。桥接 0.27.0 已补齐遗物池字段，后续刷新百科会自动使用新字段。

显示层不修改百科条目，不改变现有计算规则的参考指纹。百科与规则仍分别维护，更新后的规则兼容检查照常执行。

卡牌默认同时展示基础与升级后的费用、效果，宽屏并排、窄屏上下对照；费用和效果都来自导出的升级预览。没有升级预览时明确显示基础效果，不生成假升级值。无限升级等动态卡牌仍只显示游戏百科提供的首级升级预览。

## 本地卡面资源

从本机游戏 PCK 的资源目录和导入映射读取原生卡牌插画，核验资源校验值后转为 WebP。594 张卡牌插画可用（其中 11 张为游戏提供的测试插画），另有 64 个药水图标、298 个遗物图标。缺图条目为弃用卡牌、疯狂科学、弃用药水、测试弃牌小刀药水、弃用遗物，页面显示占位说明。没有访问 Wiki、生成替代图片或将插画发送给 AI。

资源分别位于 `data/knowledge/assets/cards`、`potions`、`relics`，版本索引为 `data/knowledge/assets/portraits.json`。页面采用小缩略图与文字并排的紧凑条目，按原始长宽比完整显示插画，不裁切顶部或底部，图片高度随原图比例变化、没有额外黑色背景框；卡名、费用、描述和升级对照由网页组合展示；插画不是包含文字与边框的整张游戏卡牌截图。

更新顺序：先在主菜单刷新本地百科，再执行：

```powershell
.runtime/conda/python.exe -X utf8 src/python/tools/knowledge/export_portraits.py
```

导出工具核对百科与本机游戏程序集指纹，不匹配时停止。页面只在资源指纹匹配当前百科时使用插画。新增资源没有写入 AI 查询的原始百科条目，不会增加决策模型的默认上下文。

Pillow 安装在项目专用环境，并登记为 Python `assets` 可选依赖。全局 Python 环境未改动。

图标导出保留透明通道，并支持游戏的 BC7、DXT 压缩纹理。美味饼干在游戏中会随角色改变图标，本百科默认使用铁甲战士版本。

升级对照在浏览器中比较展示文本，用金色加粗标出变化的数字、新增词条及费用；移除的效果另列提示。此比较仅生成页面元素，不写回百科 JSON，也不改变 AI 参考文本。
