# 战斗自主决策调优实施方案

日期：2026-10-14  
状态：设计方案，尚未按本文实施代码或配置变更。  
范围：战斗中的本地数学模型、搜索、决策分流、验证与统计；不包含非战斗选牌、商店、路线策略改造。

## 1. 目标与结论

目标是在保持战斗质量和执行可靠性的前提下，提高本地自主决策占比，降低 AI 请求次数和等待时间。

优先解决机制覆盖、候选保留和常见意图建模，再接入短期价值、抽牌价值与药水成本，最后校准 AI 转交阈值。仅调整伤害、格挡权重，无法解除发生在评分之前的覆盖拦截。

本方案中的自主决策分为严格规则、本地有限策略、经过校准的风险策略。后两者均不声称全局最优。AI 选择也不是天然正确的训练标签，需要独立验证。

### 1.1 成功指标

| 指标 | 定义与用途 |
|---|---|
| 战斗自主率 | 本地战斗选择数 /（本地战斗选择数 + AI 战斗选择数） |
| 主动决策自主率 | 排除经动作目录确认无选择空间的强制推进后，本地选择数 / 全部选择数；本地和 AI 使用相同排除条件 |
| AI 请求密度 | 每场战斗、每个玩家回合的实际模型请求数；另列失败和纠错重试 |
| 执行成功率 | 成功完成的动作数 / 已提交动作数；状态过期导致的提交前拒绝单独统计 |
| 战斗质量 | 存活、战斗胜负、敌方造成的失血、自伤、治疗、药水消耗、战斗回合数 |
| 计算成本 | 分析耗时与模型等待耗时的中位数、P95；分别统计本地与 AI 路径 |

选择比例与请求密度必须同时报告：本地一次执行一步、AI 一次计划多步，单看选择次数可能产生偏差。多次分析同一状态、等待记录和心跳不进入选择分母。

## 2. 当前实现与证据

### 2.1 决策链

1. `agent/runtime.py` 在分析前调用 `assess({}, snapshot)`，尝试强制动作、确定斩杀、结果比较等规则。
2. 未命中时，`decision/unified.py` 组织当前回合搜索、抽牌分析与有限前瞻。
3. 再调用 `assess(report, snapshot)`，尝试 `bounded_combat_search`。
4. 本地无法接管时构建 AI 请求；执行阶段仍校验新鲜状态与合法动作。

下文 Python 模块路径均相对于 `src/python/src/autoslay/`；标为“拟新增”的模块在本次审计时尚不存在。

### 2.2 当前数学模型

当前回合启发分：

```text
score = 1.0 × effective_hp_damage
      + 1.5 × effective_block
      + 3.0 × permanent_strength_gain
      + 0.0 × draw_count
```

本地策略先排除预计死亡候选，再按以下优先级排序：

```text
结束战斗 > 本回合预计失血更少 > heuristic_score > 部分抽牌边界的请求抽牌数
```

同等级再按步数、动作 ID 等确定稳定顺序。这里的 `permanent_strength_gain` 是相对于临时力量的战斗内持续力量，不等同于跨整局永久成长。

现有限制：

- `normalize.py` 将未知遗物、能力、怪物特殊钩子汇总为警告；模拟器遇到这些警告会拒绝动作转移。
- `local_combat.py` 要求搜索未截断、无搜索问题、动作覆盖一致；非允许边界的不确定性会使候选被排除。
- 药水方案不直接执行；如果它能改善斩杀或失血，会转交 AI 处理保留价值。
- 含持续力量增益的候选被本地策略跳过，虽然评分器里存在对应权重。
- 已有有限前瞻，但 `local_combat.select()` 未将其结果纳入排序。
- 当前搜索先分别保留候选、观察边界、结束回合各组的前 `top_k` 项，再由本地策略过滤。
- 抽牌组合和部分续行已有实现；`draw_forecast()` 本身不提供续行价值。

默认配置与本次读取的本机决策配置一致：普通搜索 2000 节点 / 200 ms，危险搜索 6000 节点 / 400 ms；默认深度 6，`top_k=5`。危险条件包括低血量、当前攻击可能致死、Boss。普通前瞻由调用方设为 4 分支 / 250 ms，危险前瞻按配置为 8 分支 / 600 ms，跨度 2 回合。

`complex_strategy_enabled=true` 当前会被配置校验和决策逻辑拒绝，不能通过打开现有开关获得本文能力。

## 3. S0：建立基线、归因与回放集

### 问题

现有原因包含严格证明失败、本地策略失败和等待状态。多个理由可能指向同一个根因，也可能来自不同时期的实现；直接按字符串次数排序会误判收益。`local_combat.select()` 的早返回还会遮住后续阻塞项。

### 具体解决方案

1. 固定数据截面，记录截止时间、事件 ID 列表、代码/规则/配置版本与知识指纹。按 `event_id` 去重，再关联 `analysis_id`、选择记录、提交、回执、观测。
2. 对每份快照运行当前只读分析，将结果分为：等待、本地严格规则、本地有限策略、AI 必需、无法回放。旧选择保持原样。
3. 增加诊断模式：在输入有效时收集所有独立阻塞项，而非仅返回第一个；诊断不改变执行门槛。
4. 阻塞项统一包含 `stage`、`code`、`entity_id`、`affected_actions`、`source_fingerprint`、`is_primary`。动态敌人实例 ID 单独保存，聚合时使用能力实体 ID。
5. 为每项修复做消融回放：仅开启该修复，计算“新增可接管快照”；组合修复使用集合并集，不能直接相加。
6. 按完整对局划分开发、校准、留出验证集。同一战斗相邻快照不得跨集合。数据不足时只做功能验证，不声明统计有效的自主率或误差界。

实施位置：扩展 `decision/coverage.py`、`telemetry/decisions.py`、`archive/summary.py` 与 `src/python/tools/analysis/audit_local_decisions.py`。审计脚本的输出文件名改为参数化版本，避免覆盖既有固定日期产物。

### 验收

- 每个比例均能还原分子、分母与事件 ID；等待、失败、重试不会冒充成功选择。
- 输出主动决策自主率、AI 请求密度及规则命中分布。
- 同一快照在相同版本与固定预算下的变化可追踪；超时引起的非确定性单独标记。
- 输出完整多重原因，同时区分“最先阻塞项”和“解除后仍存在的阻塞项”。

## 4. S1：机制覆盖由全局名单改为影响范围检查

### 问题

全局未知标记可能让与当前动作无关的机制阻塞整场战斗。已有芒果仅拾取生效、少量怪物图鉴过滤的特例，但尚未形成统一登记。

### 具体解决方案

拟新增 `rules/mechanism_scope.py`，将审查结论存入版本化知识数据，而非继续扩张散落在代码中的白名单。

登记字段至少包含：

```json
{
  "entity_id": "RELIC.EXAMPLE",
  "hook": "AfterObtained",
  "game_version": "待核对",
  "source_fingerprint": "待核对",
  "phase": "pickup",
  "reads": ["player.max_hp"],
  "writes": ["player.max_hp"],
  "trigger": "obtained",
  "treatment": "observed_in_snapshot",
  "evidence": "源码位置与审查说明"
}
```

上例仅说明结构，不是对任何遗物的新认证。

机制处理分为四类：

| 类别 | 条件 | 处理 |
|---|---|---|
| 已建模 | 效果、触发时机、交互已适配 | 正常执行模拟 |
| 已反映在快照 | 效果在此前已结算，当前动作不会重新触发 | 使用观测值，不重复应用 |
| 在当前比较范围内无影响 | 来源和触发条件已核对，不能影响任一竞争首步的收益与合法性 | 保留审计说明，允许比较 |
| 未知或超出覆盖 | 可能改变动作、死亡、资源或触发链 | 阻塞相关分支；必要时转交 AI |

实施步骤：

1. 先核对 `LARGE_CAPSULE`、`POTION_BELT` 的完整触发逻辑，不只核对描述文本。
2. 把已审查的芒果和图鉴特例迁入统一结构，并保持现有行为。
3. 审查 `ShouldShowMoveInBestiary`、`SetupSkins` 等候选；方法名称本身不是无影响证明。
4. 对 `AfterDeath`、随从联动、逃脱、偷牌归还等实现专门适配，不能作为界面逻辑豁免。
5. `normalize.py` 输出结构化覆盖信息；`simulation/engine.py` 按动作读写与可能触发链判断是否可模拟。
6. 即使某未知效果不影响选定动作，只要可能让另一个首步更优，也不能声称完成方案比较。需给未知替代项保守上界，或转交 AI。
7. 游戏程序集或源码指纹变化，原审查结论自动失效。把机制登记版本加入缓存键。

实施位置：`decision/normalize.py`、`simulation/engine.py`、`rules/monsters.py`、`knowledge_base/rulebook.py`、`decision/unified.py`。

### 验收

- 经证实仅拾取生效的效果不重复加数值、不再全局阻断普通出牌。
- 纯显示钩子可解除阻塞；同名但正文不同的钩子仍阻塞。
- 未知死亡钩子在可能击杀的分支上不被漏掉。
- 触发链间接修改资源、费用、合法动作时仍可检出。
- 本次新存档中的遗物问题得到逐条审查；不预设解除后所有快照必然可自主。

## 5. S2：补全常见非攻击意图

### 问题

当前归一化把缺少伤害/次数的意图作为不确定项；即使已有怪物前瞻适配，本地选择仍可能因 `Defend`、`Buff`、`StatusCard`、`Debuff` 被排除。不能把非攻击简单当成“无威胁”。

### 具体解决方案

1. 复用 `MonsterRules` 的已适配行为，建立统一的敌方行动转移接口，供当前回合结束评估和前瞻共同使用。
2. 意图结构保存类型、目标、数值、执行顺序、持续时间、来源、已覆盖效果及未知效果。
3. 按下表实现第一批覆盖，先选历史高频实体和已有源码适配：

| 意图 | 必须计算的内容 | 不能省略的影响 |
|---|---|---|
| 防御 | 敌人格挡增量、清除时机 | 下回合输出需求；多敌人选择 |
| 强化 | 力量/其他能力增量及生效时间 | 后续攻击，不将其当成零威胁 |
| 状态牌 | 生成数量、位置、手牌容量、洗牌关系 | 后续抽牌污染及手牌/回合结束触发 |
| 减益 | 目标、层数、持续时间、结算顺序 | 虚弱、脆弱等对未来伤害/格挡的影响 |
| 复合行动 | 按源码顺序依次执行 | 攻击前强化与攻击后强化不能混算 |

4. 多个敌人的行动按真实顺序模拟；击杀、召唤、随从死亡与目标失效处理必须一致。
5. 随机未来动作无公开概率时，不平均赋予概率。保存可能情境，按保守区间比较；无法建立范围则继续转交。
6. 只有“已解释并参与评价”的不确定标记才能移除。仅保证当前首步转移精确，不能自动证明结束回合安全。

实施位置：`decision/contracts.py`、`decision/normalize.py`、`rules/monsters.py`、`evaluation/combat.py`、`planning/lookahead.py`。

### 验收

- 纯防御、纯强化、塞状态牌、减益、攻击+减益分别有数值与顺序断言。
- 同一敌方行动由当前回合评估和前瞻计算时结果一致。
- 未知复合效果不能因其中攻击部分已支持而整体放行。
- 拟新增快照用例覆盖高频能力；与实测结算不一致时保留记录并停止该适配的自主授权。

## 6. S3：保留多样候选，围绕首步作比较

### 问题

搜索返回各组前 5 项后，选择器再排除药水、成长、风险方案，可能将本可使用的候选提前丢弃。多个不同序列也可能拥有相同首步，浪费候选容量。

### 具体解决方案

将“供决策使用的候选池”与“供界面展示的短列表”分离：

1. 第一层按 `(action_id, target_id)` 分组，保证每个当前合法首步有评估结果或明确未覆盖原因。
2. 第二层标注用药/不用药、抽牌边界、持续成长、结束回合等属性；同一候选可有多个属性，避免互斥桶遗漏组合。
3. 每个首步保留有限个非支配续行，而非只保留当前启发分第一名。比较维度包括失血、敌人剩余状态、耗药、成长和不确定性。
4. 仅在相同观察边界、覆盖范围和资源含义下使用支配剪枝；尚未估价的持续资源不能直接视为无价值。
5. 全部首步的摘要先进入本地选择器，最后才为 UI 截取前几项。
6. 去重时保留各首步到达同一中间状态的来源映射；复用续行计算，但不能丢掉首步竞争关系。

建议的内部结构：

```text
by_first_action[(action_id, target_id)] = {
    continuations,
    coverage,
    modeled_value,
    lower_bound,
    upper_bound,
    unsearched_alternatives
}
```

首步价值取该首步下可行续行的最佳值；未搜索部分仍计入上界或标为未知。展示数量不决定授权范围。

实施位置：`planning/search.py`、`decision/service.py`、`decision/local_combat.py`、`planning/lookahead.py`、`telemetry/decisions.py`。

### 验收

- 构造前 5 个原候选均含药水的状态，不用药水的最佳首步仍被保留。
- 多个高分序列首步相同时，另一个合法首步仍有比较摘要。
- 达到相同中间状态的不同首步能共享计算，但输出仍保留两者。
- 空序列作为“不再出牌”候选时，明确映射到合法 `end_turn`，不误当成已完成安全结算。
- 候选池扩大后仍有内存和运行时上限，预算不足明确记录。

## 7. S4：统一一至两回合价值模型

### 问题

当前按本回合失血作绝对优先级；短期承伤换输出、成长、减少未来危险的方案难以胜出。前瞻另有固定效用公式，不能直接与当前启发分相加。

### 具体解决方案

拟新增 `evaluation/combat_value.py`，统一以下评价接口：

```text
evaluate_outcome(initial, trajectory, horizon) ->
    utility_components, utility, death, coverage, uncertainty
```

建议模型：

```text
Q(s, a) = E[-w_hp(s) × L(0:H) + w_finish × I(战斗结束)
             + gamma^H × V(s_H)]
          - lambda(s) × CVaR_alpha(失血)
          - C_potion(s, a)
```

- `L` 分开记录敌方失血、自伤、治疗，效用中再按既定规则合并；不能用简单生命差冒充敌方战损。
- `V(s_H)` 评价剩余敌人的生命/格挡/能力、玩家持续能力、可续行资源、牌堆污染、已建模遗物状态。
- `CVaR_alpha` 表示最差尾部结果的平均损失；仅在概率模型有效且分支足够时使用。样本不足时使用保守损失上界，不能靠 4 或 8 个样本稳定估计极端尾部。
- 生存先通过风险约束，不能只靠一个有限死亡扣分，以免大量伤害分覆盖死亡代价。
- 格挡通过实际减少失血体现；已纳入轨迹的伤害、力量、抽牌不重复加分。`V` 只估计时间范围之外的剩余价值。

血量敏感系数可采用连续函数：

```text
missing_hp_fraction = 1 - hp / max_hp
w_hp(s) = w_hp_base × (1 + hp_sensitivity × missing_hp_fraction^2)
```

实施步骤：

1. 保留严格证明快路径，新增独立策略版本，先以影子模式输出建议，不改变动作。
2. 先验证一回合敌方结算，再启用两回合。所有比较使用相同时间终点，避免长短轨迹不公平。
3. 将现有前瞻的固定效用和内部默认 `CombatEvaluator()` 改为显式注入同一策略；让外层配置真正作用到续行。
4. 明确死亡、胜利、抽牌观察、时间耗尽、机制缺口的终止语义。
5. 以当前策略为基线，对少量预先指定参数组合做开发集筛选，冻结参数后在留出对局验证。

实施位置：`evaluation/combat.py`、拟新增 `evaluation/combat_value.py`、`planning/lookahead.py`、`decision/local_combat.py`、`config/decision/combat.default.json`。

### 验收

- 高血量下“少量承伤换下一回合确定结束”的方案可以与纯防御作真实比较。
- 低血量或坏分支可能致死时提高保护，不因平均分高就放行。
- 过量格挡不会产生额外即时价值；已结算伤害不在终值重复计价。
- 改变策略权重时，根节点与续行使用同一版本，报告完整分项。
- 对治疗、自伤、伤害减免、能力持续时间分别验证，避免净生命差掩盖机制错误。

## 8. S5：抽牌续行与持续力量

### 问题

单纯提高 `draw_option_weight` 无法区分“抽到可用牌”和“没能量、手满或抽牌受阻”。持续力量候选当前被整体跳过，导致已建模成长无法进入本地比较。

### 具体解决方案

#### 8.1 抽牌

```text
抽牌后的价值 = sum(P(抽牌结果 b) × V(真实规则下续行状态 b))
抽牌的边际价值 = 抽牌方案价值 - 可行的对照方案价值
```

1. 复用 `probability/draw.py`、`probability/card_flow.py`、`planning/lookahead.py` 的组合与洗牌逻辑。
2. 状态空间可控时精确枚举；过大时使用固定种子的抽样，记录方法、样本数、未覆盖分支与估计误差。
3. 抽牌分支保留费用、升级、附魔等版本。现有实体 ID 模板遇到多升级版本会丢失模板；拟改为按公开可区分的牌变体组织牌堆组成，来源不够时保留未知。
4. 续行计入剩余能量、手牌容量、抽牌禁止、抽牌后待结算效果、洗牌和触发链；不按“抽一张固定加分”代替。
5. 对相互比较的首步尽量使用相同抽样情境，减少纯抽样噪声引起的排名变化。
6. 真实执行仍只执行首步；抽牌后读取新快照，再重新选择，不执行假设抽到的牌。

#### 8.2 持续力量

1. 将字段语义明确为“战斗内跨回合持续力量”；与临时力量、卡牌永久成长分别存储。
2. 已支持的持续力量通过未来攻击段数、多段攻击、虚弱与易伤实际模拟体现。
3. 模拟范围之外的力量价值可用“未来可实现攻击段数 × 力量增量 × 折扣”作终值近似，但需上限和误差；不能把预计能打出的所有攻击视为确定。
4. 仅对已经覆盖的力量机制解除 `permanent_strength_gain` 整体跳过，未知能力仍阻塞。

实施位置：`planning/lookahead.py`、`probability/card_flow.py`、`decision/contracts.py`、`decision/normalize.py`、`decision/local_combat.py`、`evaluation/combat_value.py`（拟新增）。

### 验收

- 零能量、手满、禁抽时不凭空增加抽牌价值；零费牌例外由真实续行决定。
- 精确枚举概率和为 1；抽样频率明确标记为估计值。
- 同实体不同升级/附魔版本不混用费用和效果。
- 洗牌、抽牌后获得能量、抽牌后待结算伤害的顺序正确。
- 持续力量在多段攻击中按段生效，临时力量不跨回合，牌面现有力量不重复叠加。

## 9. S6：药水机会成本与用药阈值

### 问题

只要药水改善当前失血就交给 AI，会让明显该用和明显该留的情况都产生请求；反过来，单纯默认不用药又会错过救命或高收益场景。

### 具体解决方案

围绕同一初始状态分别求解：

```text
Q_keep = 保留药水的最佳可行方案价值
Q_use  = 消耗指定药水的最佳可行方案价值
Delta  = Q_use - Q_keep - C_reserve
```

上式的 `Q_use`、`Q_keep` 暂不含该药水的保留成本；合入统一 `Q` 后不得再次扣除。

`C_reserve` 第一版使用可解释的规则区间，而非训练复杂模型：

- 药水基础未来价值：按伤害、防御、抽牌、资源等类型估计。
- 后续需求：基于已知路线、已知战斗类型与当前牌组短板调整；未知未来使用区间。
- 槽位压力：当前已观测、即将可获得且会溢出的药水降低保留价值；不能假设未来必掉药水。
- 替代性：已有同功能药水或稳定能力时降低稀缺度。
- 战斗结束后的资源：胜利治疗、剩余药水、已知遗物状态共同比较。

第一批授权规则：

1. 不用药在所有已覆盖方案中确定死亡，用药方案满足风险约束且成本比较有效时，本地用药。
2. 用药收益下界高于保留成本上界加误差余量时，本地用药。
3. 用药收益上界低于保留成本下界时，本地保留。
4. 区间重叠且潜在损失较大时转交 AI。

药水本身或用药触发链未知时不启用上述规则。随机药水、生成牌、嵌套选牌先保留原转交路径；后续按机制独立适配。

实施位置：拟新增 `evaluation/potion_value.py`，修改 `decision/local_combat.py`、`planning/search.py`、`evaluation/combat_value.py`（拟新增）。

### 验收

- 同样能保命但不用药更好时正确保留；只有用药才有已建模生路时不盲目保留。
- 只省少量血与节省大量战损分别受保留成本影响。
- 多瓶药水分别比较，避免为同一收益连续消耗多瓶。
- 已消耗、不可用、目标失效的药水不会进入执行；动作前仍重新校验。
- 报告显示用药收益、保留成本、误差区间和最终选择原因。

## 10. S7：以收益误差和风险决定是否转交 AI

### 问题

现有原始分差未校准，不能直接当成置信度。任意放宽覆盖阈值可能让未知分支变成虚假的安全结论。精确模拟误差、抽样误差和策略近似误差需要分别处理。

### 具体解决方案

采用分层授权，不修改严格证明的含义：

1. 严格规则继续优先。
2. 已覆盖且满足当前有限策略要求的情况继续走本地策略。
3. 新的短期策略根据候选收益范围与风险校准结果决定授权。
4. 未知关键机制、状态不完整、无法给未知替代项建立上界时交给 AI；状态尚未稳定则等待。

对每个首步输出 `Q_hat`、`lower`、`upper`、`bound_kind`、风险范围和覆盖信息。

```text
a* = 当前建议首步
robust_gap = lower(a*) - max(upper(b), b != a*)
regret_upper = max(0, max(upper(b), b != a*) - lower(a*))
```

- 所有竞争首步均已纳入且 `robust_gap > margin`，可按收益区间支持的优势自主选择。
- 若区间重叠，但 `regret_upper <= epsilon(s)` 且满足风险约束，可在已验证的低风险范围内自主选择。
- 低血量、不可逆资源消耗和未知死亡风险使用更严格的 `epsilon(s)`；超过范围转交 AI。

区间必须注明性质：精确界、在明确假设下的保守界、经过留出验证的统计区间。统计区间允许失覆盖，不能被命名为确定性证明。未经校准的启发分不生成伪精确区间。

未覆盖概率质量为 `1-p` 时，只有已知合理的全局收益界 `[Q_min, Q_max]` 才能写：

```text
lower = 已覆盖分支的加权收益下界 + (1-p) × Q_min
upper = 已覆盖分支的加权收益上界 + (1-p) × Q_max
```

如果无法建立收益界，则保持未知。不得只对已覆盖分支重新归一化，然后称为完整期望。抽样中观察到的频率也不能直接替代精确覆盖质量。

### 校准流程

1. 对确定性效果，用执行前预测与执行后观测检查数值误差和状态误差。
2. 对短期动作价值，用小规模充分求解局面、独立审查案例或受控可复现试验建立参考；普通历史日志只有实际执行动作的结果，不能据此给所有未执行动作打真实分。
3. 将模拟错误、候选漏搜、抽样波动、终值近似分别记录；不能用一个平均误差掩盖机制错误。
4. 参数选择与误差校准使用独立对局，留出集只作最终评估；必要时按多个首步比较调整统计区间的同时覆盖。
5. 没有足够校准证据的状态类型继续使用旧策略或转交 AI。

实施位置：`decision/deterministic.py`、`decision/local_combat.py`、拟新增 `calibration/combat.py`、`telemetry/decisions.py`、`configuration.py`。现有 `calibration/tuning.py` 主要针对整局选项估值，不能直接当成战斗校准已完成。

### 验收

- 原始同分、大分差均不会绕过关键机制检查。
- 留出集报告区间覆盖率和高风险失覆盖案例，不只报告与 AI 的一致率。
- 候选池缺少某合法首步时，没有上界就不能按“明显优胜”授权。
- 每次转交 AI 有单一主因和完整附加原因，便于下一轮优化。

## 11. S8：按不确定性分配搜索预算

### 问题

现有深度优先搜索采用固定预算；截断后本地策略整体拒绝。覆盖扩大后，抽牌、零费牌、多目标和药水组合会放大这一问题，但当前日志尚未显示它是主要瓶颈。

### 具体解决方案

1. 优先展开潜在斩杀、明显减少伤害、已覆盖资源组合，但动作排序不能代替对其他候选的覆盖。
2. 使用迭代加深/可中断的优先搜索，按首步共享续行缓存；每次中断保留已求得的下界与未展开分支上界。
3. 状态键包含影响续行的能力、资源、手牌修饰、遗物计数、待结算效果等；不能为提高命中率省略关键字段。
4. 对真正等价的卡牌排列减少重复；同实体但不同升级、附魔、费用、触发记录不能直接合并。
5. 第一阶段使用当前预算；仅当高风险或候选接近且预计继续搜索能减少不确定性时追加预算。
6. 分别记录 `time_limit`、`node_limit`、`depth_limit`、`mechanics_boundary`，避免全部笼统称为搜索不完整。
7. 截断但可证明未展开分支不会改变首步时，才允许按界限授权；没有有效上界时仍转交或沿用既有已覆盖策略。

实施位置：`planning/search.py`、`planning/lookahead.py`、`decision/unified.py`、`decision/cache.py`、`config/decision/analysis.default.json`。

### 验收

- 精确小状态集上，与穷举相比首步和最优值一致。
- 预算增加不因候选丢失导致已知最佳可行收益下降。
- 超时输出可解释，所有未搜索分支可追踪。
- 在机制覆盖相同的数据集比较耗时、节点数、截断率与新增可接管量；不把“多给时间”当成算法收益。

## 12. 配置、执行和观测台的一致性改造

### 12.1 配置版本

先在现有 `combat`、`analysis`、`autonomy` 策略中设计新字段与版本迁移，不直接修改旧配置常量的含义。

| 策略 | 拟增加内容 |
|---|---|
| combat | 统一效用权重、生命敏感系数、终值策略、药水保留成本参数 |
| analysis | 候选池规模、首步覆盖、分阶段预算、抽样方法与误差输出设置 |
| autonomy | 新策略的关闭/影子/执行模式、经校准风险阈值、校准产物版本 |

默认配置与 `.runtime/local/agent/profiles.json` 覆盖需要一起校验与迁移；只改默认 JSON 不保证实际生效。新增字段需同步 `configuration.py` 的合并、校验、导入导出和迁移；旧配置应保持旧行为。

本方案不规定未经校准的上线权重或风险百分比。试验参数、阈值和每次变更都写入报告，验证后才确定执行配置。

### 12.2 执行一致性

- 新策略输出独立的 `decision_basis`，例如拟新增 `calibrated_combat_strategy`，并保留旧字段兼容。
- 同步修改 `agent/runtime.py` 和本地执行器；当前运行时仅对 `bounded_combat_strategy` 传入有限策略执行参数，不能只新增选择器而不接入执行路径。
- 每次仍校验状态来源、哈希、合法动作、目标和执行器占用；抽牌等观察边界后必须重算。
- 若执行器重新分析，须验证建议与原报告一致或生成新报告；不能把旧选择证据套到新状态。
- 对已提交但结果未知的动作继续阻止重复提交，与 AI 路径保持一致。

### 12.3 归档与 UI

报告新增策略版本、校准版本、效用分项、首步竞争摘要、区间性质、机制覆盖、搜索完整度、耗药成本和转交原因。

`src/web/public/sidebar-combat.js` 展示“为何自主/为何交给 AI”，并区分严格证明与有限策略。选择事件与真实请求事件分开计数；实际执行前的影子建议不能计入自主率。

## 13. 实施批次与交付清单

### 批次 A：建立基线并解除已证实的误拦截

范围：S0、S1，以及 S2 的常见已知意图。S3 可同步作为独立改动推进。

交付：冻结回放清单、机制登记、来源指纹验证、意图转移、逐项消融报告、候选池回归案例。

进入下一批的条件：未引入机制数值错误；关键未知仍正确阻塞；新增可接管快照能够逐条解释。自主率数值目标在完整基线复算后设定，不能预先承诺 70% 或 90%。

### 批次 B：提升本地策略的比较能力

范围：S4、S5、S6。

交付：统一效用、一至两回合比较、抽牌/力量/药水分项、影子报告、参数候选评估。

进入下一批的条件：不同模块不重复计价；抽牌与未知分支报告完整；在参考局面中能解释与旧策略不同的选择。

### 批次 C：校准分流与优化复杂状态计算

范围：S7、S8、配置迁移、运行时接入、UI/归档一致性。

交付：冻结校准产物、留出验证结果、策略开关、执行前检查、完整转交原因统计。

启用顺序：离线回放 → 在线影子观测 → 已验证状态类型的小范围启用 → 扩大覆盖。每次只扩大一个有证据支持的状态类别。

### 回滚规则

出现确定性模拟与真实结算不一致、动作/目标错误、重复提交、关键未知被错误放行时，立即禁用对应新规则；保留严格快路径与此前通过验证的策略。回滚通过策略版本和独立开关完成，不删除历史记录。

战斗质量出现下降迹象时，按完整对局分析并报告置信范围；样本不足则保持影子模式。平均失血、治疗、自伤分开检查，避免仅凭净生命变化判断改善。

| 影子观测 | 新策略在真实输入中的稳定性与误差 | 影子建议与实际轨迹记录；不冒充反事实收益 |
| 实战 | 自主率、请求密度与战斗质量是否同时改善 | 多对局统计、完整版本信息、质量指标置信范围 |

推荐构建的关键案例集：

1. 已结算拾取遗物与纯显示钩子；来源变更后重新阻塞。
2. 死亡联动、逃脱归还、未知触发链仍阻塞相关动作。
3. 防御/强化/状态牌/减益和复合敌方行动。
4. 候选前列全为药水或同一首步时，其他可行首步不丢失。
5. 承伤换斩杀、低血量保护、过量格挡、治疗与自伤。
6. 禁抽、手满、洗牌、混合升级牌、抽牌后待结算效果。
7. 临时/持续力量、多段攻击及牌面力量去重。
8. 救命药水、低收益耗药、多瓶药水、未知随机药水。
9. 搜索截断、区间重叠、未覆盖概率质量、校准失效。
10. 状态变化、执行器忙、提交结果未知、影子建议不进入真实计数。
