# 本地战斗批次决策实施记录

日期：2026-10-15。实施依据为本次讨论确认的方向：本地独立作出可接受的决策；Top K 比较操作批次及其重新决策场景；生命属于整局资源；建模不完整不自动转交 AI。

本记录补充并调整此前以严格接管和校准授权为主的战斗方案。旧严格模型、校准工具及历史报告保留作兼容和误差分析，默认战斗选择采用本地批次入口。

## 当前调用链

```text
当前公开状态
  → 牌组能力、路线与生命资源概况
  → 生成到观察/目标边界的操作批次
  → 已支持效果模拟 + 明确标注的近似续行
  → 同一资源目标评分、排序与 Top K 接近分数取舍
  → 新鲜状态下重新选择、归档实际批次
  → 逐步校验并执行批次
  → 抽牌/选牌/回合/资源新信息/结算偏差时重新本地决策
```

唯一合法推进、已核对无回血/成长等资源取舍的确定斩杀仍可走快路径。这些优化不先用旧当前回合排序覆盖批次选择。新批次报告存在时，`assess()` 优先采用其选择；默认 Agent 不在战斗中构造模型 provider。

## 候选与批次

- `planning/combat_batches.py` 新增批次候选、续行评价和排序。
- 批次可包含多张攻击、攻防组合、强化、用药，也可停在抽牌或未知效果结算。
- 同首步的不同结束状态会保留；不同顺序到达等价状态会合并。可见属性相同、可互换的卡牌实例不重复占用 Top K，升级、费用、附魔、待结算效果和目标差异仍保留。
- 抽牌方案的评分会展开可能结果与真实续行，未知分支使用明确的估计，不丢弃再伪称完整覆盖。实际批次在抽牌处停止，不包含假设抽到的牌。
- 批次执行范围与评价范围分开。评价使用有限回合模拟和窗口之外的能力/威胁估计；预算不足时保留可行批次，按可见威胁与终值估计继续选择。
- 搜索启动前的知识准备成本单列，避免第一次加载知识就耗尽整个搜索预算。搜索时间、节点、深度和生成限制继续记录。
- Top K 是批次列表，不是按首张牌分组。完整报告保存批次内的预测状态轨迹，简报不重复输出这些大字段。

## 统一价值与整局资源

`evaluation/combat_resources.py` 提供：

1. 攻击比例、每张抽牌的基础输出/防御、持续力量、额外抽牌、能量、攻击段数、低费比例等可并存的能力指标。
2. 战后回复及可见固定回血牌的资料。当前明确建模燃烧之血的胜利回复；复杂回血触发仍可能使用单步近似并在实际结算后重选，不声称全部回血机制已精确适配。
3. 连续、随缺血增加的生命价值；可见四步路线内可能的精英/Boss 压力及火堆机会成本代理。未知路线有默认资源保留需求，不要求预知未来才能作决定。
4. 窗口之外的输出、防御、力量、击杀时间和承伤压力代理。力量通过未来输出或敌方攻击影响该值，避免再次固定加一遍成长分。窗口末尾仍选择下一已知招式；紧接非攻击强化时可再观察一次已知转移来估计后续压力，避免把强化回合当作未来零威胁。

评分分项包括整局生命价值变化、预计后续生命成本、结束战斗、剩余敌人资源、牌堆污染、药水成本、未知效果代价和死亡代价。分项和等于方案分数；预计生命、回血等原始资源量单独保存，不能再加一次。

生命价值同时比较两个方案的回复：64 血时不承伤，胜利后为 70；承伤 6 后胜利为 64，差值仍保留。不能因为有燃烧之血就视为免费承伤。回血估计受缺失生命上限限制。

火堆机会成本、持续防御和窗口外击杀时间属于显式启发式代理，尚未精确求解“某条路线必须休息、具体放弃哪张牌的升级”。当前不以流派标签强制决定攻防，也不声称统计校准后的整局胜率。

## 本地选择与模型缺口

默认先比较预计生存情况，再比较统一价值。所有已知方案均可能死亡时，仍选择估计最可行的方案。Top K 在 `tie_margin` 范围内接近时，优先少耗药、少失血和少近似项，并采用稳定排序，不请求 AI 裁决。

未知遗物、能力、牌和回合结束钩子保存于估计缺口；启发式状态副本可以继续计算已知效果。严格模拟器的未知机制拒绝语义保持不变，新结果标为 `uncalibrated_estimate`，不称为证明或安全上界。无法模拟的合法操作可按可见描述作单步代理，结算后重新观察；固定回血估计封顶，自伤扣除生命价值。

此前严格校准仍可作为独立分析工具，但其产物不是本地批次执行的前置许可证。来源/版本不兼容、状态未就绪等不能可靠执行的情况等待处理，不自动向 AI 请求战斗动作。战斗外流程本轮仍保留原处理方式，尚未完成整局无 AI 自主化。

## 执行与降级

`execution/deterministic.py` 增加实际批次执行，保留持久提交身份及全局执行锁：

- 执行前按新鲜状态重新选择，归档这次实际批次及其依据。
- 每一步校验会话、对局、战斗、版本、控制状态、合法动作和目标；每个请求提交之前先落盘。
- 普通确定性操作符合预期时继续批次，不每打出一张牌就重新选择。
- 抽牌、选牌、回合变化、目标或资源新信息出现时停止批次并重新决策。
- 比较玩家与敌方能力、生命、能量、星、手牌、牌堆、药水、遗物计数及相关运行字段。手牌描述/附魔等新信息变化也会重选，不因正常的信息边界停用整个策略。
- 数值结算不符时停止当前批次，将相关卡牌/药水模型记录到 `.runtime/local/agent/combat-batch-models.json`。后续该模型需要结算后观察，仍保留本地选择；降级记录进入缓存键，不能复用降级前的旧长批次。
- 父动作等待选牌时，只允许与同一父请求绑定的子选择继续；父动作不重放。战斗内嵌套选择按当前提示及可见卡牌收益逐次在本地处理。
- 已提交而结果未知的动作继续阻止重复提交。

Agent 在本地战斗模式下启动不要求已配置模型或凭据。执行服务 `/autonomy` 也会使用同一本地批次入口。UI 展示完整操作批次、重新决策场景、资源价值、回血和估计缺口，并明确是启发式选择。

## 配置

`config/decision/autonomy.default.json` 新增 `combat_batches_enabled=true`，默认启用本地战斗批次。仍尊重本地主配置的全局启用及暂停状态。

`combat.batch` 新增：

| 字段 | 默认值 | 含义 |
|---|---:|---|
| hp_weight | 2.0 | 整局生命基础价值 |
| hp_sensitivity | 3.0 | 缺血时的边际价值增长 |
| rest_opportunity | 8.0 | 火堆机会成本代理 |
| reserve_fraction | 0.4 | 未知路线的生命储备参考 |
| unknown_penalty | 3.0 | 近似或未知效果的价值代价 |
| tie_margin | 1.0 | Top K 接近分数范围 |
| terminal_enemy_hp_weight | 0.4 | 剩余敌人资源代理 |
| death_penalty | 10000.0 | 死亡价值代价，另有预计生存排序 |

使用既有配置合并、校验、导入导出流程。旧 `strategy_mode`、校准 ID 和 `complex_strategy_enabled` 不用于开启批次，不能把旧校准开关关闭理解为批次关闭。显式设 `combat_batches_enabled=false` 可回到旧兼容路径；旧模块保留以便对照，不是默认入口的第二套排序。
