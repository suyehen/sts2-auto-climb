## 战斗评估如何解释

确定性候选仍按生存、当前击杀、损血和收益排序。跨回合情景单独展示，不会偷偷改变排序，也不会把未知分支当成零损血。Codex 根据两部分报告选择候选，包括需要观察的抽牌前缀。

未来敌人动作不读取隐藏脚本。默认情景重复当前可见攻击，只是一种压力情景；调用方也能显式提供最多四种情景，每种必须为所有活敌人填写攻击数组，空数组明确表示不攻击。跨回合默认深度 2，最多 3。

抽牌使用公开牌堆组成的组合分布；分支太多时使用固定种子采样。抽到目标牌的概率与抽牌后的有界后续选择分开计算。精确分布和采样会分别标记；采样比例是经验估计，目前没有置信区间。

报告中的 `covered_probability` 表示已估值分支的概率质量；`conditional_metrics` 只在这部分分支上计算。出现未知升级版本、抽牌／消耗钩子或预算耗尽时，覆盖可能低于 1。条件存活／完成比例只适用于所列情景，不能称为真实胜率。剩余损血上限隐藏时沿用保守预测。

满手牌、禁止效果抽牌、普通洗牌以及已有周期遗物计数规则继续沿用。多个计数按各自周期处理，无相关遗物时不引入额外等待搜索。完整跨战斗拖延成本和后续战斗收益仍属于情景估计。

## 统一量化标准

战斗外比较使用共同的“启发式效用分”。伤害、防御、抽牌、力量、生命、金币和风险权重公开；血量越低，防御与生命越值钱。报告保留改变前后指标及各项代价，便于解释和调参。

这些资源指标是按开局抽牌和能量需求计算的代理量，并不是完整前三回合对战模拟。未知牌的贡献不进入已知分量分数，报告明确列出 `unknown_cards` 和 `score_scope`；因此已知分量的增减仍可能漏掉配合。未知候选不获得虚假的总分。

商店有保留金币候选，组合受金币和药水容量约束；价格折扣、买后变化和满药水栏替换须另行解释，实际购买后重读状态。事件保留描述和悬浮提示，不完整悬浮或条件／概率文字无法解析时，交由 Codex 解读，再通过 `evaluate_run_choices` 提供明确结构化效果。概率只能来自可见信息或明确标注的调用方假设，程序不猜概率。

## 配置与迭代入口

- `config/decision/combat.default.json`：当前回合收益权重。
- `config/decision/analysis.default.json`：普通／危险局面的节点与时间预算，跨回合深度、分支数、采样种子。
- `config/decision/run.default.json`：选牌、商店、事件、篝火的共同权重及组合搜索预算。
- `config/decision/relic-timing.default.json`：周期遗物时机评分。
- `data/knowledge/catalog/encyclopedia.json`：本地百科，仍用 `refresh_encyclopedia` 显式刷新。
- `data/knowledge/mechanics/game-0.111.0.json`：经核实的版本化机制。
- `data/replays/manifest.json`：公开状态回放清单，可增加新版本与新机制场景。

修改配置后下一次分析会重新读取，缓存键包含配置内容、百科内容哈希、状态、情景和模块版本。缓存最多 64 份报告，返回深拷贝；命中仍更新会话、状态版本和就绪状态。缓存不复用执行权限或旧动作回执。更新规则代码后须重启 Python 常驻服务；新增 C# 桥接字段须重新构建、部署并正常重启游戏。

## Codex 的游玩流程

1. 优先调用 MCP `analyze_decision`，或常驻服务 `/decision`，一次获取当前阶段的统一报告。旧 `analyze_combat` 和 `/analyze` 保留为兼容入口，仅做原来的当前回合分析。
2. 看覆盖缺口、当前生存／击杀结果和必要的跨回合情景；只比较少量候选。普通确定局面不反复查百科，不重复计算同一状态。复杂或接近致死的局面才扩展情景／预算。
3. Codex 明确选择动作。确定性战斗前缀可以用 `prepare_plan.py` 转成计划，经 `execute_plan`／`/plan` 连续执行。抽牌、随机、选择器、结束回合或数值偏差立即返回 Codex；抽牌后必须读取真实新手牌。
4. 奖励、商店、事件、地图等仍逐项执行，重读价格、实例和合法动作。通用选择器无法确认语义时用显式 add／remove／upgrade 比较。
5. 新界面恢复动作也必须来自新鲜的 `legal_actions`；不会直接强制跳过模态、穿过地图或修改游戏状态。

常驻执行避免每张牌启动 MCP 子进程；缓存减少重复计算；候选及报告减少重复工具往返。它们无法承诺缩短 Codex 模型本身的思考时间。既有实战日志中 MCP 启动约 515 ms、动作和游戏结算约 807 ms 中位数，但样本很少且有长尾，不是速度承诺。脚本无法把结算中的动画与后端等待进一步拆开。

## 仍有明确边界

没有覆盖游戏全部机制。随机消耗、新施加虚弱、升级、未知生成／抽牌钩子、隐藏剩余伤害额度等仍停在观察边界。本次固定回放的频率审计首先指出剩余损血额度、随机消耗、虚弱和升级边界，供下一轮按实际出现频率扩展。

没有经过大量实战校准的胜率、通用药水模拟或完整未来敌方回合。路线不预测隐藏奖励或连续 HP 转移，少量遗物／药水的估值仍是公开假设。框架、入口、配置和回归已接齐，后续新增机制可以单独适配及验证，无须改动整套系统。不需要 14B 模型、embedding 或 reranker 才能运行本次功能。
