# AutoSlayTheSpire 数学模型详细说明与评估

> 归档说明（2026-10-18）：本文保留当时的设计、实现或验证结论；归档不表示全部实现或验收通过。当前事项状态见 [文档首页](../README.md)，正文中的“当前”“尚未”等表述以原记录日期为准。

核对日期：2026-10-11。本文描述当前代码已经实现的模型，不把计划中的能力视为已有能力。默认参数以 `config/decision/` 为准。游戏规则适配版本为 0.111.0；卡组评估模块 1.2.0，情境修正模块 1.0.0，可执行知识规则 1.1.0，模拟器 0.6.0。全量支持仍未完成，最新覆盖与实施状态见 [全量知识规则与决策面板实施记录](全量知识规则与决策面板实施记录.md)。

## 1. 模型的性质和评估边界

目前确实进行了数学建模，但它是若干局部模型的组合：规则模拟、有限搜索、抽牌概率、资源价值评分和风险修正。它还不是一个统一求解“最大化整局通关概率”的模型。

| 部分 | 实际目标 | 方法 | 输出的含义 |
|---|---|---|---|
| 当前回合战斗 | 优先避免预测死亡、完成击杀、减少预测失血，再比较资源收益 | 确定性转移 + 有预算的深度优先搜索 | 已支持规则下的候选动作序列 |
| 抽牌 | 计算抽到不同牌组合的概率 | 超几何分布或抽样 | 组合概率，不是假设一定抽到好牌 |
| 有限未来回合 | 比较指定敌人情境下的短期结果 | 概率分支 + 局部搜索 | 有覆盖范围限制的条件期望 |
| 抓牌、删牌、升级 | 比较修改前后的卡组代理价值 | 资源平均值 + 协同、环境、约束修正 | 启发式分数差，不是胜率变化 |
| 商店、事件、休息、路线 | 比较局部资源收益和风险 | 分项评分及有限组合搜索 | 启发式建议 |
| 周期遗物 | 比较延后结束战斗对下一场前几回合的价值 | 多计数器联合推进 + 成本区间 | 满足指定假设的时机参考 |
| 校准 | 检查预测误差、比较参数配置与独立评价的一致性 | 记录、按局划分、有限配置筛选 | 待评审参数建议，不自动训练或替换策略 |

**没有统一的分数单位。** 战斗分、卡组分、未来情境效用和遗物时机分使用不同权重和时间范围，不能直接相加。当前也没有将所有模块代入同一个 Bellman 方程，没有完整的隐藏状态推断或全局最优保证。

Codex 仍是最终决策者：模型提供候选、分项、未知项和预测；执行器按合法动作目录执行 Codex 选定的动作。百科负责提供可查询的规则资料；百科条目存在，并不代表模拟器已实现该机制。

## 2. 输入、状态和约束

### 2.1 战斗状态

记玩家生命为 `H`，上限为 `Hmax`，格挡为 `B`，能量为 `E`，手牌集合为 `Hand`。

模型读取：玩家生命、格挡、能量、力量及临时力量，虚弱/脆弱及持续时间；手牌实例、费用、类型、目标类型、升级等级及描述；抽牌堆、弃牌堆、消耗堆的公开组成；敌人生命、格挡、易伤、力量、虚弱、伤害上限和可见攻击意图；药水和可用目标；已适配的遗物状态和周期计数器。

每张牌以实例 ID 区分。抽牌概率主要按实体 ID 的数量建模。若同实体有不同升级版本且不能唯一建立模板，未来分支会被标为不能可靠模拟，而不是随意选一个版本。

不读取隐藏抽牌顺序、未来 RNG、未公开事件结果或完整未来敌人行动脚本。敌人意图不完整时会标记不确定性。存在未知战斗效果警告时，精确动作转移会停止，不把未知效果当作零。

### 2.2 可行动作

支持固定费用卡牌的出牌及合法目标、已建模药水，以及部分结束回合参考。需要满足：费用非负且能量足够，牌在当前手中，目标合法，药水尚未消耗。

X 费用及星星 X 费用不能进入精确模拟。固定星星费用会检查并扣除星星资源，但卡组长期星星价值尚未适配。药水规则现有 11 个兼容条目，包含直接伤害、格挡、能量、力量、易伤、抽牌和复合效果，部分效果只支持观察边界，并非全部药水及交互。

搜索会评价每一个动作前缀，包括“不再出牌”的空前缀。显式结束回合候选用于周期遗物的等待分析；这不意味着执行层平时不能结束回合。

手牌上限固定为 **10**，其他上限目前被拒绝而非自动适应。

## 3. 确定性战斗转移

### 3.1 效果顺序

出牌先扣能量、移出手牌，再按规则适配器规定的顺序执行效果。完成后才进入弃牌堆或消耗堆。抽牌在效果中途发生时，打出的牌尚未进入弃牌堆，因此不会被这一次洗牌重新抽到。

实体资料来自全量百科，执行程序来自版本化结构规则库，基础效果解释器不再按卡牌名称分派。源码核对覆盖全部 961 个条目，但尚不能解释全部程序；未知逻辑保持未支持，并阻止精确模拟。

当前卡牌 54、药水 11、遗物 17 个条目的参考指纹兼容，包含仅到观察边界及部分遗物适配；此数不能理解为全部效果和交互完整支持。准确清单由覆盖工具或面板实时读取，本文不再维护重复的实体白名单。

在概率前瞻中，抽牌边界保留待结算效果和使用中的卡牌；分支抽牌后继续结算，可展开已建模的“抽牌、获得能量、再抽牌、伤害”序列。真实执行器仍在抽牌处停下，读取真实结果后继续决策。

| 效果 | 当前处理 |
|---|---|
| 普通伤害、多段伤害、格挡、能量、力量、易伤 | 已适配的规则可按顺序计算 |
| 敌人已有易伤时增加攻击段数 | DISMANTLE 的条件段数单独处理 |
| 抽牌 | 执行到抽牌边界，取得新状态后再决策；有限前瞻可展开部分概率分支 |
| 自损生命 | 适配部分减伤；隐藏累计上限影响不能可靠确定时停止 |
| SECOND_WIND 消耗非攻击牌 | 仅处理明确类型和已知交互；未知消耗钩子停止 |
| 新施加敌人虚弱、随机消耗、选牌升级 | 返回观察/选择边界，不能直接假定后续结果 |
| 未适配的生成牌、触发链、遗物交互 | 不自动获得数值规则，需要规则适配或 Codex 单步处理 |

### 3.2 伤害与格挡

当前可见手牌文本通常已包含既有力量、虚弱等修正，不能重复加一次。当前回合新增力量记为 `ΔStr`。每段伤害先计算：

```
d0 = max(0, 文本伤害 + ΔStr)
d1 = floor(1.5 × d0)                 若目标易伤，否则 d0
d2 = min(d1, 单段伤害上限)          若存在已知上限，否则 d1
吸收 = min(敌人格挡, d2)
敌人生命减少 = min(敌人生命, d2 - 吸收)
```

多段攻击逐段处理，格挡逐段消耗。未来抽到的百科标准模板会另行应用既有力量和虚弱；虚弱采用 `floor(0.75 × 伤害)`，脆弱格挡采用 `floor(0.75 × 格挡)`。这些准确性仅限已适配规则及其交互。

部分已适配机制包括首张牌格挡翻倍、特定条件下敌人攻击减半、每次生命损失减少 1。部分每回合生命损失上限的剩余额度不公开，模型不能凭当前生命反推；预测使用保守额度，相关精确转移可能被拒绝。

主要敌人全部被击杀时可判定战斗结束；残留召唤物不会被虚构为已经造成的额外伤害。

## 4. 当前回合的评分与搜索

### 4.1 失血预测

将仍存活敌人的可见攻击展开为逐段 `a1 … ak`；先应用已知减半效果。用出牌后的格挡依次抵挡：

```
absorb_t = min(剩余格挡, a_t)
剩余格挡 -= absorb_t
loss_t = max(0, a_t - absorb_t - 每次生命损失减免)
attackLoss = Σ loss_t
L = 出牌自损生命 + attackLoss
```

已知回合生命损失上限会约束攻击预测。`L` 不包含未知敌人脚本、未知状态伤害或未适配触发链。

### 4.2 候选排序

设 `D` 为实际减少的敌人生命，`Beff = min(出牌后格挡, 调整后的可见攻击总量)`，`Sperm` 为本回合新增永久力量：

```
Qcombat = 1.0D + 1.5Beff + 3.0Sperm + 0.0×抽牌数量
排序键 = (预测不死亡, 已完成击杀, -L, Qcombat)
```

排序按字典序，前一项优先级高于全部后一项。意味着：在预测都存活且都未击杀的两条路线中，少失血 1 点优先于任意大的最后一项收益。它不是一个平滑的“血量与输出交换率”。

抽牌数量的当前直接权重为零；抽牌候选另报观察边界和有限前瞻，不能理解为所有抽牌路线已经用同一尺度排入普通候选。

### 4.3 搜索预算

采用深度优先搜索和状态去重，评价动作前缀；达到观察边界、死亡或最大深度后停止展开。

| 参数 | 普通模式 | 危险模式 |
|---|---:|---:|
| 最大节点 | 2,000 | 6,000 |
| 时间预算 | 200 ms | 400 ms |
| 最大动作深度 | 6 | 6 |
| 返回候选 | 5 | 5 |

低血量比例不超过 0.35、可见总攻击不低于当前生命，或可识别的当前 Boss 房，可触发危险预算。Boss 识别依赖实际快照里可用的地图信息，不能保证所有战斗快照都会识别。

**这是预算内找到的较优候选，不能称为最优解。** 搜索遍历顺序、深度、时间截断和规则覆盖都可能影响结果。

## 5. 抽牌概率、满手与生成牌

### 5.1 概率公式

抽牌堆共 `N` 张，其中想要的牌 `K` 张，不放回抽 `d` 张：

```
P(至少一张目标牌) = 1 - C(N-K,d) / C(N,d)
```

若各实体数量为 `N_i`，抽到各实体数量为 `n_i`：

```
P(n_1,…,n_m) = [Π C(N_i,n_i)] / C(N,d)
Σ n_i = d
```

例如 7 张牌里只有 1 张目标牌，抽 3 张，抽到它的概率为 `3/7 ≈ 42.86%`。不能按“抽三一定能摸到”制定后续确定动作。

相同实体的数量组合按照物理牌组合数加权，不是每种数量组合等概率。可完整枚举时用有理数计算；超出组合预算则按固定随机种子抽样，不放回抽取物理牌。

### 5.2 容量和洗牌

```
可用手牌位置 = max(0, 10 - 当前手牌数)
实际效果抽牌 = min(请求数量, 可用位置, 可用牌数量)
```

效果抽牌被禁止时为零。普通回合开始抽牌与“效果抽牌禁止”在底层流转规则中有区分，不能将所有抽牌一概关闭。

手牌已满而没有抽上来的牌留在抽牌堆。已知牌生成时先占空位，超过容量的生成牌进入弃牌堆；生成不等同于抽牌，不受同一个禁止抽牌开关控制。**有这些流转原语，不等于所有生成牌来源都已适配。**

抽牌堆耗尽时，先抽完当前抽牌堆，再从已知弃牌堆洗入继续抽。消耗堆不参与。需要洗牌但弃牌组成未知时停止精确计算。

### 5.3 实际概率预算

通用概率模块默认可枚举至 5,000 种组合，否则默认抽样 2,000 次。但实时有限前瞻会传入更小预算：普通模式约 4 个分支/样本，危险模式约 8 个。

例如 7 张互不相同的牌抽 3 张有 35 种组合；实时前瞻可能只抽样 4 或 8 次。不能把通用模块的默认 2,000 次当作实时决策的实际样本量。当前没有为这种小样本结果输出置信区间。

## 6. 有限未来回合模型

### 6.1 时间范围和敌人情境

默认回合深度 2，可配置 1～3；不是完整战斗。未来普通抽牌默认 5、能量默认 3，周期遗物奖励另加。普通模式前瞻时间约 250 ms，危险模式约 600 ms。

最多处理 4 个显式未来敌人攻击情境。未提供时重复当前可见攻击，**这是情境假设，不是预测敌人真正会连续使用该招式。** 不同敌人情境单独报告，没有各自发生概率，也没有跨情境统一期望。

前瞻覆盖普通候选前 3 条和观察边界候选前 3 条。未来局部出牌搜索约 150 节点、25 ms、深度 6，比较前 2 条普通候选和前 1 条观察边界。

### 6.2 终局效用

在指定情境和有限时间范围内：

```
Ufuture = (终点生命 - 初始生命)
          - 0.4 × 残余主要敌人生命
          + 50 × I(已结束战斗)
          - 1000 × I(玩家死亡)
```

`I` 为条件成立时等于 1 的指示函数。上述 0.4、50、1000 是启发式常量，没有经过大量实战拟合。

它与当前战斗字典序目标不同，也与卡组评分不同。当前并未使用这个未来效用自动重新排列全部根节点普通候选。

### 6.3 覆盖率与条件期望

设分支概率为 `p_b`，该分支可继续模拟的覆盖率为 `c_b`：

```
c = Σ p_b c_b
E_known[f] = Σ(p_b c_b E_b[f]) / c
```

报告的是覆盖部分上的条件期望，包括生命损失、敌人残血、生存和战斗完成情况。未覆盖部分没有被证明成功，也没有被证明失败。

举例：覆盖率 40%，覆盖分支全部完成战斗，报告的条件完成率可以是 100%；这不能解释为总完成率 100%，更不能解释为真实游戏通关率 100%。

**当前未来局部策略比较条件效用时没有统一惩罚未覆盖概率质量，可能偏爱覆盖少但已知分支很好的路线。** 这是评估时应重点检查的偏差。

### 6.4 回合推进的简化

推进时主要执行：按可见攻击扣生命，弃置手牌，清格挡，重置能量，移除临时力量，减少部分状态持续时间，更新周期计数器和未来攻击情境。少量特殊牌有单独处理。

尚未完整模拟保留、所有虚无、回合结束触发、敌人召唤/成长/塞牌/改变意图等。出现禁止效果抽牌或敌人虚弱时，当前未来续算还可能直接停止；底层知道普通抽牌与效果抽牌的差别，不代表前瞻已经贯通所有相关状态。

## 7. 卡组价值：抓牌、删牌与升级

### 7.1 情境变量与权重

情境 `x` 包含生命、金币、下一房间、敌人数量、禁止效果抽牌、药水空位、手牌容量，以及可选的预期出牌后手牌数和可用抽牌数量。

生命、金币、药水空位和部分禁止抽牌状态可自动读入。下一房间、敌人数量及未来手牌占位通常需要明确提供；不能假定已自动推断全部未来环境。

定义防御/生命紧迫程度：

```
u = 1 + 2 × (1 - H/Hmax) + 0.5 × I(下一房间为精英或Boss)
```

| 系数 | 默认值 |
|---|---:|
| 伤害 `wD` | 1.0 |
| 格挡 `wB` | 1.2 |
| 抽牌 `wR` | 2.0 |
| 能量 `wE` | 4.0 |
| 永久力量 `wS` | 3.0 |
| 易伤 `wV` | 1.0 |
| 诅咒/状态负担 `wC` | 8.0 |
| 生命成本 `wH` | 2.0 |
| 金币 `wG` | 0.04 |
| 事件下行风险 `wRisk` | 0.5 |
| 力量×额外段数 | 1.5 |
| 抽牌×零费牌密度 | 2.0 |
| 消耗非攻击牌格挡修正 | 1.0 |
| 每张牌组厚度惩罚 | 0.12 |

### 7.2 卡牌本体价值

每张牌从已适配规则提取伤害 `d_i`、格挡 `b_i`、抽牌 `r_i`、能量 `e_i`、永久力量 `s_i`、易伤 `v_i`、自损 `h_i`、攻击段数 `k_i` 和非攻击牌消耗格挡 `z_i`。

```
Intrinsic_i = d_i + 1.2b_i + 2r_i + 4e_i + 3s_i + v_i
              - 2h_i - 8×I(诅咒或状态)
```

这是中性资源参考值。费用单独展示，**没有在此式直接扣费用**；费用主要在整组评估里处理。没有为每张牌单独训练一个基础权重。

临时力量、给敌人加力量、条件双倍段数等效果可能只有警告或部分贡献。比如 FIGHT_ME 的敌人力量代价在战斗模拟中有处理，但卡组本体评分没有完整扣除该代价。卡牌有数值不意味着数值已涵盖其完整效果。

### 7.3 费用与平均资源近似

卡组 `D` 有 `n` 张牌，默认开局抽牌数 `m=min(5,n)`，默认能量 3：

```
demand = m/n × Σ max(0, cost_i)
α = min(1, 3/demand)                demand=0 时取 1
A_x = α × m/n × Σ x_i
```

`A_x` 是平均资源代理量，不是真实随机手牌中最优出牌的期望。这是整个模型的重要近似：同一个 `α` 作用于所有牌，包括零费牌；没有逐手牌求解费用组合。

得到的能量 `A_e` 会获得分数，但不会反过来提高 `α`。所以“先产能量，再打高费牌”的卡组收益可能被低估或失真。

### 7.4 有效抽牌

预期出牌后手牌数 `h*` 默认 4；空位 `F=max(0,10-h*)`。

```
R_eff = 0                                          若禁止效果抽牌
R_eff = αm/n × Σ min(r_i,F)                         否则
```

若明确提供可用抽牌数 `Aavailable`，每项再取 `min(r_i,F,Aavailable)`。

这是逐牌容量上限，并未顺序更新多张抽牌牌打出后的手牌容量，也没有默认模拟每次洗牌供给，因此多个抽牌效果可能被高估。默认 `h*=4` 也不是对所有小卡组、先天牌、保留牌的真实手牌预测。

### 7.5 完整分解公式

设攻击牌密度 `a=#攻击/n`，可用零费牌密度 `q=#零费且非诅咒状态/n`：

```
Xhits = αm/n × Σ max(k_i-1,0)
Tnonattack = max(0,m-1) × #已知非攻击类型牌/n
Zblock = A_z × Tnonattack × 1.0
AreaExtra = αm/n × Σ[ d_i×(敌人数-1) ]，仅累计群攻牌

基础 B = A_d + 1.2A_b + 2A_r + 4A_e + 3A_s + A_v

协同 S = 3A_s×a
         + 1.5A_s×Xhits
         + 2R_eff×q
         + 1.2Zblock

环境 E = 1.2A_b×(u-1)
         + 1.2Zblock×(u-1)
         + AreaExtra
         + A_v×(a-1)

约束 C = 2×(R_eff-A_r)

成本 P = -8m×#诅咒状态/n
         -2u×A_h
         -0.12n

V(D,x) = B + S + E + C + P
```

解释：易伤的基础项加环境修正后相当于 `A_v×攻击密度`；禁止抽牌时抽牌基础项被约束项抵消，抽牌与零费牌协同也消失；抽牌牌的格挡、伤害等其他贡献仍保留。

力量协同和消耗格挡协同使用“平均值×平均值”代理，没有计算同时抽到相关牌、出牌先后、剩余费用和触发次数的联合分布。协同分也可能与已有基础项发生重复估值，需要校准或结构修正。

### 7.6 抓牌、删牌、升级

```
Δ抓牌 = V(D+新牌,x) - V(D,x)
Δ删牌 = V(D-指定实例,x) - V(D,x)
Δ升级 = V(D替换为实际升级版本,x) - V(D,x)
Δ跳过 = 0
```

升级必须有实际百科版本；删牌按实例匹配，不能删不可移除的 Eternal 牌。可评分候选按差值排序，未知候选保留未知理由。

已有卡组中的未建模牌不会被当作完整无价值牌，但其未知贡献暂不计入已知部分总分；仍可能输出暂定差值。这可能遗漏协同并改变排序。带条件效果警告的牌也不一定被完全排除评分。

### 7.7 可手算的检查例子

构造卡组：2 张费用 1、伤害 6 的攻击牌；2 张费用 1、格挡 5 的技能；1 张费用 0、抽 3 的技能。满生命，单敌人，无其他效果。

```
n=m=5；demand=4；α=0.75
A_d=9；A_b=7.5；A_r=2.25
a=0.4；q=0.2；F=6
基础=9+1.2×7.5+2×2.25=22.5
抽牌协同=2×2.25×0.2=0.9
牌组厚度成本=-0.6
V正常=22.8
```

若禁止效果抽牌，`R_eff=0`，抽牌协同为零，约束抵消 4.5 分：`V禁止抽牌=17.4`。

若明确出牌后有 9 张手牌，只有 1 个空位，`R_eff=0.75`：约束为 `-3`，协同为 `0.3`，`V近满手=19.2`。

这只是公式演示，不是某真实卡组的实战评级。它也暴露近似：零费抽牌牌被全局 `α=0.75` 一起折减。

## 8. 商店、事件、休息和路线

### 8.1 商店

枚举当前可买项目的购买/跳过组合及删牌服务。约束总支出不超过金币、购买药水数不超过空位、每件项目最多一次、同一牌不能被重复删。最多约 500 节点、300 ms，返回前 5 个方案。

```
Ushop = V(购买后卡组)-V(原卡组)
        + Σ 药水/遗物局部价值
        - 0.04×金币支出
```

保留全部金币是零增益基线。不会完整模拟后续商店价格、购入遗物引发折扣、药水替换满药水栏或金币机会成本随未来变化。

当前少量物品价值规则如下，均为启发式：

| 物品 | 当前局部价值公式/假设 |
|---|---|
| 格挡药水 | 格挡量×1.2×u×0.7，0.7 为使用收益折算 |
| 燃烧之血 | min(6,当前缺血)×2×u，按一次战后回复 |
| 灯笼 | 固定 4 分 |
| 钨合金棍 | 3×2×u，假设三次受影响的生命损失 |
| 皇家枕头 | min(15,缺血)×2×0.5，假设休息概率 0.5 |
| 永冻冰相关规则 | 7×1.2×min(1,5×能力牌数/n) |

未知物品价值为未知。上述条目时间范围并不一致；已拥有遗物的全部长期效果，也没有统一反馈到卡组特征和商店组合里。

### 8.2 事件

自动文本解析只支持严格的生命和金币增减语法。存在剩余条件、概率或复杂文字时不自行编造结果。悬浮提示会保留供 Codex 判断，但不是全部自动转成数值规则。也接受明确提供的结构化加牌、删牌、升级、物品和概率结果。

对结果 `j`：

```
U_j = ΔV卡组 + 2u×(实际回复-失血)
      + 0.04×(获得金币-失去金币) + Σ物品价值
EV = Σ p_j U_j
Downside = Σ p_j max(0,-U_j)
Score_event = EV - 0.5×Downside
Fatal = Σ p_j I(结果导致死亡)
```

概率必须明确提供且和为 1。死亡风险单独输出；已知数值、是否有已知致死结果、事件分构成排序键。它不是方差惩罚或 CVaR。

同一选项内生命和金币按顺序变化，回复受上限限制。但计算卡组差值和紧迫程度时仍用原始情境，没有在事件失血后重新计算整组防御价值。

### 8.3 休息

休息回复：`2×u×实际可回复生命`。升级：比较实际升级牌的 `ΔV`。其他未适配选项保持未知。没有计算未来地图下“现在回复”和“靠战后回复恢复”的完整长期差别。

### 8.4 地图

路径分是可见各房间固定分之和，最多 500 节点，保留前 5 条：

| 房间 | 分数 |
|---|---:|
| 休息 | `5u` |
| 商店 | `min(金币/40,6)` |
| 精英 | `4-4u` |
| 普通战斗 | `1-u` |
| 未知 | `0` |
| 宝箱 | `4` |
| Boss | `0` |
| 古人 | `1` |

整个路径沿用当前生命和金币，不模拟途中收益、战斗失血或升级。未知房间零分是路线占位值，不能解释为真实收益为零。由于 `u≥1`，精英分永远不为正：该模型不能充分表达“当前战力足够，应主动打精英获取长期收益”。

## 9. 多个周期遗物的跨战斗时机

### 9.1 计数器模型

每个遗物独立表示为 `(周期 p_i, 当前计数 c_i, 抽牌奖励 r_i, 能量奖励 e_i)`。当前已适配：

| 实体 | 周期 | 抽牌 | 能量 |
|---|---:|---:|---:|
| HAPPY_FLOWER | 3 | 0 | 1 |
| PENDULUM | 3 | 1 | 0 |
| POLLINOUS_CORE | 4 | 2 | 0 |

推进 `k` 次玩家回合开始：

```
触发次数_i = floor((c_i+k)/p_i)
新计数_i = (c_i+k) mod p_i
```

所有遗物联合计算，不要求它们都停在“满层数减一”。没有这些遗物时该分析关闭。计数器未知不会假定为零；同实体多实例暂需要专门实例适配。

### 9.2 下一场收益

默认考察下一场前 3 回合，普通抽牌每回合 5，既有手牌 0；这些是显式假设，可改成第一回合已有大量手牌等情境。

在第 `t` 回合，所有遗物抽牌奖励共享同一个手牌容量和供给上限：

```
BaseActual_t = min(普通抽牌, 空位, 可用牌)
TotalActual_t = min(普通抽牌+Σ遗物奖励, 空位, 可用牌)
ExtraDraw_t = TotalActual_t-BaseActual_t
F(c) = Σ[t=1..3] 0.7^(t-1) × (1×ExtraDraw_t + 2×ExtraEnergy_t)
```

若回合开始抽牌本身被禁止，则实际抽牌均为零。首回合本来就抽满 10 张时，首回合遗物抽牌的边际收益为零，后续回合奖励仍可有价值。能量价值暂为线性，不判断是否有可花掉能量的牌。

### 9.3 等待成本与保守收益

考虑额外等待 `k=0..3` 回合结束战斗。总结束成本的生命区间为 `[L_k,U_k]`，额外资源惩罚为 `R_k`。相对立即结束：

```
ΔF_k = F(推进k次后的计数)-F(当前计数)
净收益下界 = ΔF_k - (U_k-L_0)×1 - (R_k-R_0)
净收益上界 = ΔF_k - (L_k-U_0)×1 - (R_k-R_0)
生存约束 = 当前生命-U_k ≥ 1
```

只有完成击杀证据、生命上界和规则支持齐全，且立即结束基线也可靠时，才可能建议比较等待。净收益下界大于零才算“在给定假设下有正收益”。这些不是普遍成立的未来保证。

**当前自动战斗适配器通常只能证明立即击杀成本。** 等待一回合的当前可见失血不等于等待后直到击杀的总成本上界，所以会保持未知、返回参考。当前没有完整自动求解拖若干回合后的击杀路径。

等待期间本场触发的奖励会展示，但没有完整续算时不强行估值。不能为了对齐计数器忽略失血、敌人成长或资源消耗。

## 10. 校准和实战证据

### 10.1 三类数据必须分开

1. 分析记录：当时公开状态、候选、参数版本和分项。
2. 决策意图：Codex 或人工选择了哪一条，理由是什么；它本身不是执行成功证据。
3. 后续观察与独立评价：动作/回合/战斗/整局结果，以及人工复核或配对实战复核。

记录关联游戏版本、会话、状态版本、策略指纹、角色、进阶与 trial。当前整局胜负标签由调用方报告；没有自动验证每个标签，不能把所有标签视为已核实实战。

### 10.2 预测误差

对可比较的回合结果：

```
error = 观测生命损失 - 预测生命损失
平均偏差 = mean(error)
平均绝对误差 = mean(abs(error))
```

先按局聚合再跨局平均，避免一局很多样本支配统计。实际生命差可能包含回复及额外动作；意图也可能没有完整执行，因此需要确认比较边界，不能把所有误差直接归因为评分权重。

### 10.3 当前参数筛选

参数候选是有限配置集，不是连续优化或自动训练。默认包含 baseline、提高抽牌价值、提高力量价值、提高防御和生命价值等配置。

只对可建模的抓牌、删牌、升级、跳过使用独立偏好标签。模型自己选择产生的标签不能作为“正确答案”。同一局不拆到训练和验证两边；通过 trial ID 哈希将约 20% 划为留出局。

对于独立评价“应选 A 而不是 B”：

```
margin = Score(A)-Score(B)
agreement = 1       margin>1e-9
            0       margin<-1e-9
            0.5     其余
配置成绩 = 各局内平均agreement，再跨局平均
```

先在训练局选配置，再比较该配置与基线在留出局的表现。至少 10 局训练、5 局留出且留出一致性更好，才形成待评审建议；不会直接改默认权重。

**这些门槛只是筛选门槛，不是统计充分性的证明。** 尚未提供配置比较的显著性检验、重复使用留出集控制或因果识别；不能从“某张牌被拿后输了”直接推出该牌权重应下降。

### 10.4 胜率报告

可比较的整局按游戏版本、角色、进阶和策略指纹分组；冲突标签剔除，放弃局不算胜负。报告胜率及 Wilson 约 95% 区间。它不消除种子难度、操作失误和未验证标签带来的偏差，目前也没有自动配对同种子试验。

截至本次模型核对，上一轮工程验证为 140 项 Python/MCP/HTTP 检查通过，另有 6 个公开 Boss 状态回放，其中 2 个真实数值转移匹配。这些支持部分规则和接口正确性，**不证明策略胜率**。实战校准目录尚无已记录选择意图和完整校准局；默认权重未经大量实战校准。

## 11. 执行效率与模型的关系

规则计算、工具往返、游戏动画和 Codex 思考是不同耗时来源。搜索预算约束计算时间，不能约束 Codex 总决策时间。

执行器可接收最多 12 步明确动作序列；每步核对会话、状态版本、合法动作和目标。出现抽牌、随机结果、选牌或模型预测不符时停下，返回新状态供 Codex 决策。缓存依赖完整状态和模型/配置版本，不会拿旧状态继续执行。

提高搜索预算不能自动解决工具往返和思考耗时；增加连打长度也不能消除观察边界。效率评估应分别记录这些时间。

## 12. 建议重点评估的缺口

| 优先级 | 问题 | 为什么会影响决策 | 可检验方法 |
|---|---|---|---|
| 高 | 各模块目标和量纲不统一 | 当前保血、未来击杀和长期成长可能互相冲突 | 同状态比较各模块排序与理由 |
| 高 | 费用统一按平均比例折减 | 零费牌被折减，产能量顺序与最佳出牌组合丢失 | 小卡组枚举所有手牌及可行出牌，与代理值对比 |
| 高 | 概率前瞻分支过少、条件覆盖偏乐观 | 低概率好分支可能显得过强 | 35 种组合完整计算，对照 4/8 次抽样及覆盖率 |
| 高 | 规则覆盖和条件副作用不完整 | 看似强牌遗漏代价、生成/触发链无法算完 | 按机制建立覆盖矩阵及游戏转移对照 |
| 高 | 尚无实战权重校准数据 | 数值大小缺乏效果证据 | 开始完整记录、独立复核、按局留出验证 |
| 中 | 均值相乘协同、可能重复估值 | 强化组合被高估或低估 | 联合抽牌与顺序枚举，检查边际收益 |
| 中 | 卡组抽牌容量没有动态更新 | 多张抽牌牌和满手场景失真 | 逐步流转对照公式结果 |
| 中 | 未来敌人重复当前意图 | 没有反映真实战斗节奏 | 使用已观察敌人行为情境，分别报告敏感性 |
| 中 | 遗物等待缺完整结束成本上界 | 无法可靠自动权衡拖回合 | 延迟结束路线模拟与实际完成成本核对 |
| 中 | 地图固定值、精英价值非正 | 忽略战力成长和长期奖励 | 同种子比较路线及成长结果 |
| 中 | 事件情境不随失血重新评分 | 事件后防御紧迫度变化未反馈 | 同结果用新旧情境重新评估 |

建议评估时分别回答：规则对不对、概率对不对、代理评分能否保留合理排序、未知范围是否诚实、执行是否跟随决策、整局表现是否改善。工程测试通过与策略更强应分开验收。
