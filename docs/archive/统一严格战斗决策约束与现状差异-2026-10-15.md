## 1. 严格模式的定义

严格模式应对应一整套战斗决策：状态读取、相关机制覆盖检查、合法方案生成、模拟、随机分支处理、持久资源估值、统一选择、提交及执行验证。不能仅将一个斩杀动作是否通过证明称为严格模式。

严格模式内遇到影响当前方案比较或执行正确性的未知、不支持机制、状态缺失、非法提交、预测不一致，必须停止 agent 并给出具体异常；不得静默切换文本估值、清除警告继续模拟、忽略未知替代方案或转交其他决策层。

不允许把严格定义为“默认假设模型正确”或“当前模型没有算出死亡”。

## 2. 现有一步斩杀限制的逐项判断

| 当前限制 | 必要性判断 | 统一严格决策应采用的条件 |
|---|---|---|
| 遗物和敌人必须在斩杀白名单 | 白名单是覆盖证明手段，不是永久业务要求 | 证明相关伤害、死亡、复活、转阶段、战斗结束和持久效果已覆盖；未知则停止 |
| 玩家无能力、敌人无额外能力、隐藏能力列表为空 | 一律为空过度限制；可观测和可建模必要 | 已存在能力必须完整观察或有可靠源码规则；相关未知机制停止 |
| 禁止 X 费用、星数 X 费用 | 不是策略必要条件 | 正确读取费用与效果关系并模拟，未支持时停止 |
| 禁止附魔或负面附着 | 一律禁止不是策略必要条件 | 修饰数据和效果必须被模型覆盖；未支持时停止 |
| 不允许持有药水 | 不必要 | 将可用药水与保留成本纳入同一候选比较 |
| 只允许出牌和结束回合 | 是现有证明器的能力限制 | 支持的战斗动作统一建模；未知动作需诊断，不能悄悄排除有决策意义的替代选项 |
| 无标准化错误、无警告 | 标准化正确和语义完整必要；所有警告一律阻止需按类别判断 | 影响合法性、结果或资源比较的警告是硬错误；诊断信息应有明确等级，不能把未知降为普通提示 |
| 完整牌组不可打牌和回合末效果核对 | 相关影响必须核对；与当前及后续比较无关的对象不必机械逐个阻断 | 使用效果依赖和资源变化范围证明无影响，不能凭猜测跳过 |
| 包括当前付不起的手牌也核对 | 在可能通过资源变化启用、或存在被动/回合末触发时必要 | 依赖分析判定可达性与触发范围，不限于当前可打集合 |
| 只允许少数 damage/block 等效果 | 是现有实现支持范围，不是严格决策应长期遵守的策略 | 对已支持的抽牌、回血、成长、金币、生成等统一建模；未支持则停止 |
| 一个动作就必须结束战斗 | 只适用于一步斩杀快捷处理，不适合作为完整决策要求 | 比较完整可执行方案；快捷路径只是同一决策器的等价优化 |
| 动作后生命必须不变 | 不必要 | 比较失血、回血和其他持久收益；不能排除有成本但值得的终结路线 |
| 没有观察边界 | 对一次确定性单动作证明有意义；不是整个严格模式要求 | 支持已建模的观察节点，暂停下发后续动作，读取真实状态再继续严格决策 |
| 敌人生命都归零 | 实际获胜必要，但单纯归零不充分 | 根据游戏获胜条件及死亡、复活、转阶段、召唤、结束触发完成后的状态判断 |
| 多条路线只比较生命和最大生命 | 对通用严格决策不足 | 比较所有相关持久资源和下一战条件；其余维度必须相同或有明确价值比较 |

减少机械白名单不表示放宽未知处理。限制应从“禁止某类内容”改成“相关机制必须具备覆盖与验证”。

## 3. 战斗结束后的比较对象

一个终局应是所有结算触发完成后的持久状态，至少按相关性纳入：

- 生命、最大生命、金币。
- 药水实例、槽位及其他消耗品。
- 卡牌永久成长、升级、附魔、永久费用、牌组增删等。
- 狩猎、贪婪之手等击杀奖励，以及其他相关终结触发。
- 跨战斗保留的遗物计数、充能和状态。
- 下一场首回合受其影响的抽牌、能量、触发顺序和其他收益。
- 角色专属持久资源及已确认受战斗操作影响的奖励/后续条件。

开心小花、摆动球已有周期计数适配：规则表分别声明周期 3 的额外能量 1 和额外抽牌 1。**这不能自动证明其跨战斗保存、开战递增和重置语义已完整实现。**评估下一战首回合前必须核对这些规则。

周期计数的价值不是越大越好，需要按周期、开战递增、重置及其他触发计算下一战收益。囤积计数也不能脱离为拖回合付出的生命、药水和其他成本独立优化。

## 4. 什么情况下停止、什么情况下继续

| 情况 | 严格模式目标行为 |
|---|---|
| 枚举时发现费用不足、目标死亡等明确非法候选 | 不生成或剔除；这是正常搜索，不需要停止 agent |
| 决策器把非法动作当作可执行动作选出或提交 | 停止并抛出非法方案/模型不一致异常 |
| 桥接层公开未知动作，且可能影响决策 | 停止并报告未支持动作；行政动作等排除范围需明确定义 |
| 影响当前决策的未知卡牌、能力、遗物或结算 | 停止并报告缺失机制和受影响对象 |
| 对象可证明不影响当前比较 | 可以忽略其无关维度，但必须有可复核依据 |
| 已建模抽牌、选牌或敌方随机结果 | 到观察节点暂停后续下发；观察后继续同一严格决策流程 |
| 动画忙碌、正常异步结算 | 有界等待；超时后停止并报告，不静默无限等待 |
| 状态版本正常变化，旧方案未提交 | 废弃旧方案，重新读取和严格计算；不是降低决策标准 |
| 已提交动作的结果未知 | 停止后续提交，查询同一请求回执；不得重发产生重复动作 |
| 预测与实际不一致 | 停止并保存预测/实际差异，不能仅降级后自动继续 |
| 搜索预算耗尽 | 不能宣称完整比较；按明确要求扩预算或停止。只有具备已验证充分界限并满足规定执行标准时才可能提前结束搜索 |

“未知机制”与“已知概率分布中的未观察结果”不同。后者可严格建模；前者不能用经验分弥补。

## 5. 严格终局比较是什么意思

现有 `terminal_comparison.py` 枚举经过认证、当前回合内能够结束战斗的路线，要求转移完全覆盖、无观察边界、手牌数量逐步减少，并在独立预算内搜索完毕。

它构造战后 Outcome，当前适配器传入的维度只有生命和最大生命。随后比较：

- 相等：持久结果相同。
- 支配：所有比较维度不差，至少一项更好。
- 取舍：有的维度好、有的差，不能凭无权重支配证明直接确定。
- 未知：覆盖、确定性或结果结构不满足证明条件。

它还要求最佳当前胜利路线达到已认证的战后资源上界，以排除等下一回合可能更好的情况。当前通过限制卡牌/遗物等类型排除了大部分其他持久变化，不能将这个小范围比较器当成通用的跨战斗资源决策。

未来“终局比较”应是统一决策器中的状态评价步骤，不应是另一套独立出牌规则。达到同一个胜利标志不代表后续策略条件相同；依赖不同计数和牌组成长的终局不能仅标记为同一 continuation 就视为等价。

## 6. 只有一套实际决策层

目标结构：

```text
严格状态/覆盖验证
  → 统一动作模型
  → 统一方案搜索与概率/观察节点
  → 统一战斗及跨战斗资源评价
  → 统一选择标准
  → 严格执行和结果验证
```

允许多个实现模块、搜索优化和共享辅助函数；不允许不同模块各自定义一套可能绕过严格要求的决策标准。

一步斩杀快捷路径只有在证明其结果与统一决策等价时才可提前返回。仅证明“现在能杀”不足以跳过金币、成长、遗物计数及拖回合收益比较。

当前代码仍保留严格快速规则、批次选择、旧当前回合策略、校准策略等独立分支，且批次模式存在清除覆盖阻断、文本回退和预测不匹配后降级继续等行为。它们与此处目标不一致，需要代码改造，不能靠改文档称作已实现。

本轮仅补充设计分析和架构约束，未更改运行时决策或启动/停止正在运行的 agent。
