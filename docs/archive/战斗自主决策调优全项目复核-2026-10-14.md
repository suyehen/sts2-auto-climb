## 关键证据与可复现缺口

### 1. 多重诊断不能完整显示解除首阻塞后的剩余问题

`decision/local_combat.py` 检查 `local_combat_card_modifier_not_certified`，但 `decision/coverage.py::diagnose()` 没有同等认证检查。复现：在有效 live 测试快照中同时加入 `RELIC.NEW` 和手牌 `AFFLICTION.UNKNOWN`，调用 diagnose 并指定机制阻塞为主因。返回未知遗物与主因，未返回修饰认证阻塞。仅在修饰恰好作为传入 primary 时附加该字符串，不能满足完整独立诊断。

诊断目前主要由离线审计调用；在线报告中的 mechanisms 检查不等同于这套完整多重原因结果。应对照全部选择器门槛补齐诊断，并保持诊断不改变授权。

### 2. 非攻击意图已有适配，但两个评价路径尚未统一

`rules/monsters.py::effects/step` 已处理部分非攻击和攻击后复合效果，并拒绝未知调用和攻击前效果顺序。`evaluation/combat.py` 使用 enemy.attacks 计算失血；`decision/normalize.py` 将没有完整伤害/次数的意图加入 uncertain_intents。`planning/lookahead.py` 调用 MonsterRules.step，但 `decision/local_combat.py` 按当前候选指标筛选，不消费前瞻结果。故不能说没有非攻击适配，也不能说 S2 已验收。

### 3. 候选池仍与展示容量耦合

`planning/search.py` 每组执行 `del group[budget.top_k:]`。方案要求独立决策池、有限非支配续行和逐首步覆盖摘要；当前实现改善了被药水或相同首步挤占的问题，但不是完整的 S3 结构。`decision/service.py` 的前瞻也仍传入展示候选和观察短列表，没有传入全部决策池。

### 4. 两回合模型存在，外层策略尚不能统一控制续行

`planning/lookahead.py` 的 terminal 使用固定 HP/剩余敌人 HP/胜利/死亡公式；visit 和显式攻击情境调用默认 `CombatEvaluator()`。外层 combat 策略未注入。当前 local_combat 仍先胜利、再本回合失血、再启发分排序，不能完成 S4 要求的统一时间终点、生命敏感系数和风险约束比较。

前瞻结果明确命名为 conditional_metrics 并报告 covered_probability，没有将未覆盖质量隐式作为零收益。这个保守语义应保留；后续授权仍需全局合理界限或保持未知，不能直接使用这些条件均值宣称完整期望。

### 5. 抽牌变体问题贯穿 C# 快照和 Python 模型

`src/csharp/bridge/Bridge.cs` 的 draw_composition 按卡牌实体 ID 聚合。Python CombatState 的牌堆组成也按实体 ID；`lookahead.templates_for()` 检出多升级版本后删除该实体模板。当前实现能保守降级，但没有实现方案要求的公开可区分牌变体组成。只改 Python 模板表不足以完成 S5，还需核对快照能提供的合法公开变体信息；不应暴露隐藏牌序或 RNG。

## 建议补齐顺序

1. 完成 S0：补全独立诊断，区分规则/有限策略回放分类，关联实际调用/提交/回执，输出方案成功指标；冻结完整对局划分与超时记录。
2. 完成 S1/S2/S3：从登记到动作影响检查；当前回合与前瞻共享敌方转移；独立候选池预算、非支配续行及全部合法首步未覆盖摘要。
3. 在现有前瞻、抽牌、力量基础上实现 S4/S5：统一策略注入、轨迹损失分项、公开牌变体、完整概率/抽样误差报告；先输出影子建议。
4. 完成 S6：同状态用药/留药成对比较、可解释保留成本区间及未知触发链阻塞。
5. 以独立参考局面及留出对局完成 S7，再联合 S8 引入有效分支界限和预算分配；最后接入新配置/运行时/UI，并按已验证状态类别逐步启用。

不建议通过放宽 coverage、打开 complex_strategy_enabled、增加 draw 权重或单纯增加预算来代替上述工作。当前安全降级属于已具备的正确行为，不能为提高自主率而绕过。
