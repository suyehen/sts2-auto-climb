# 常驻执行与动作序列

> 归档说明（2026-10-18）：本文保留当时的设计、实现或验证结论；归档不表示全部实现或验收通过。当前事项状态见 [文档首页](../README.md)，正文中的“当前”“尚未”等表述以原记录日期为准。


执行层 1.0.0、决策服务 0.3.0，适配游戏 0.111.0。C# 桥接保持 0.20.0，此次无需重启游戏或部署 DLL。

## 职责与调用流程

Codex 读取局面、比较计算报告并明确选择动作序列。执行器不挑选候选、不抓牌、不决定药水或结束回合时机，也不在后台持续游玩。一次计划最多 12 步。

`src/python/src/autoslay/execution/` 包含序列校验、进程互斥和常驻服务；`bridge/` 管游戏通信，`rules/` 与 `simulation/` 管效果计算，`evaluation/` 与 `planning/` 管评分和候选，`knowledge_base/` 管统一知识访问。各模块独立维护。

常驻服务只监听 `127.0.0.1:18766`，使用项目本机桥接 token 鉴权，复用 HTTP 连接。启动本身不产生游戏动作，也不会自动开启控制。游戏桥接仍负责最终的状态版本、合法性和请求去重。

```powershell
./launch/Start-ExecutionService.ps1
./.runtime/conda/python.exe src/python/tools/runtime/execution_client.py state
./.runtime/conda/python.exe src/python/tools/runtime/execution_client.py analyze
# Codex 阅读报告后明确指定候选索引；以下 1 只是调用示例。
./.runtime/conda/python.exe src/python/tools/game/prepare_plan.py .runtime/logs/resident-analyze.json --candidate 1 --output .runtime/logs/chosen-plan.json
./.runtime/conda/python.exe src/python/tools/runtime/execution_client.py plan .runtime/logs/chosen-plan.json
```

`prepare_plan.py` 只转换明确指定的候选，绝不执行游戏。还可用 `--group observation_boundaries` 选定需要重新观察的前缀。不能自动固定使用排名第一的候选：分数是启发式，Codex 还要考虑未来回合、首领机制和覆盖限制。

MCP 新增 `execute_plan(plan)`，提供相同的序列校验。已有 `act` 与 `execute_decision.py` 保留兼容单步入口，菜单和选牌子界面仍可使用。当前会话无需等待 MCP 工具列表更新，可直接使用常驻服务客户端。

## 校验与中断

计划携带独立 `plan_id`、`session_epoch`、`run_id`、`expected_state_version` 和 `steps`。首次校验局面版本，之后每步使用最新快照版本提交。每步检查实际 legal_actions 和目标，并比对预测的血量、格挡、能量、敌我力量、易伤、当前攻击、手牌身份及费用、升级等级、牌堆组成、药水和回合。

已覆盖的确定性结果吻合才继续。抽牌、随机消耗、未知效果、选牌、弱化与力量的舍入不确定性、阶段变化、结束回合、错误或预测不符都会停止，并返回完整快照。空抽牌且已证明没有未知交互时可以继续；实际抽到牌则必须回到 Codex。

每个子动作使用固定请求 ID；完整计划和请求在派发前原子写入 `.runtime/logs/plans/`。同一计划重复调用只读取台账，内容不同则拒绝。中途进程退出留下 `running` 记录时也不自动续跑：查询已保存的动作 ID，核实结果后再决定剩余步骤。跨 MCP/常驻执行器的计划使用 OS 文件锁互斥；进程退出后锁自动释放。已有单步接口仍受游戏桥接的版本检查约束。

## 战斗计算覆盖

- 钨合金棍：逐次扣除实际未格挡损血，支持多段攻击和自损血。
- 律动残余：当前剩余额度不可见，敌人攻击预测标为保守上界，最多 20；自损血动作保留观察边界，不能假定当前仍有完整额度。没有读取游戏私有计数。
- 小型扭蛋与皇家枕头：在当前已发生的战斗中不影响已覆盖动作；永冻冰晶的能力触发仍未模拟，当前支持的牌没有能力牌。
- 随从：所有主要敌人死亡即可结束战斗，不把随从剩余生命伪算成造成的伤害。
- 血债支持自损后攻击；祭品支持能量图标读取、能量和抽牌前缀；上勾拳支持伤害与易伤前缀，新施加虚弱返回观察；余烬支持伤害前缀后随机消耗边界。
- 武装保留升级选牌边界；重振精神根据可见卡牌类型消耗非攻击牌、逐张格挡，排除已打出的自身。有未知消耗触发或军团交互时停止。彼岸嚎叫支持手牌群攻，其消耗堆自动施放仍属结束回合观察范围。
- 格挡药水支持已显示的固定格挡及使用后移除；其他药水仍需要扩展。

百科描述、规则计算和执行授权是三件独立的事。读取了描述不等于可以精确模拟其所有交互；候选的观察边界不等于完整回合结果。敌人 Buff/Debuff 意图的未知结果继续明确报告。

## 验证结果与耗时

实战第 17 层首领战、第 4 回合，Codex 明确选择“与我一战攻击神官 → 巨像”。单次提交完成两步，服务记录总耗时 **1870 ms**，动作等待分别约 **1058 ms / 790 ms**，结果为 HP 55/80、格挡 4、能量 0。最终规则重新回放，两步完整可比较投影均吻合。未结束回合。

旧单步样本每步 MCP 启动约 0.5 秒、读状态合计约 0.05 秒、打击结算约 0.54 秒；两次打击完成时间间隔约 14.5 秒，包含模型思考和工具往返，未单独测量模型时间。新序列消除了已确定步骤之间再次等待 Codex 的间隔。以上是本机单次实测，不是所有牌或回合的速度保证。结束回合仍需等待游戏敌人动画和结算。

实战记录：`.runtime/logs/speed-validation-result.json`；最终投影回放：`.runtime/logs/speed-validation-replay.json`。序列台账逐步保存请求、预测、回执、前后快照和动作耗时。常驻查询仍需启动轻量客户端 Python；它不再为每张牌启动 MCP 服务。

最终 **93 项 Python/MCP 回归通过**，包括真实 MCP STDIO、真实常驻 HTTP 鉴权与跨请求连接复用、OS 锁互斥、派发前持久化、重复请求不重放、超时/未知回执/选择/随机/抽牌中断、预测偏差停止、逐次减伤、损血上界、随从退场、重振精神和格挡药水。C# 无修改。
