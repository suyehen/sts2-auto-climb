# 决策层设计与验收

> 归档说明（2026-10-18）：本文保留当时的设计、实现或验证结论；归档不表示全部实现或验收通过。当前事项状态见 [文档首页](../README.md)，正文中的“当前”“尚未”等表述以原记录日期为准。


日期：2026-10-09。当前交付：第一阶段原型及抽牌机制/周期遗物时机扩展，不是完整游戏模拟器。扩展细节见 [抽牌机制与遗物时机](抽牌机制与遗物时机.md)。

本层只提供计算和候选方案，Codex 决定最终动作。新增工具不出牌、不喝药、不启动对局，不修改控制模式。

## 模块边界

| 目录（src/python/src/autoslay 下） | 职责 | 当前状态 |
| --- | --- | --- |
| decision/contracts.py | 不可变状态、动作、转换结果和可替换模块接口 | contract 1.1.0 |
| decision/normalize.py | 读取桥接快照，隔离游戏字段，识别未支持机制 | adapter 1.1.0，固定游戏 0.111.0 |
| rules/registry.py | 卡牌效果顺序与可见文本数值读取 | rules 0.1.0 |
| simulation/engine.py | 纯函数式效果执行，不含策略或游戏调用 | simulation 0.2.0 |
| probability/draw.py | 超几何概率、多重集精确分布、固定种子采样 | probability 1.0.0 |
| planning/search.py | 有限时间、节点数及深度的候选搜索 | search 0.2.0 |
| evaluation/combat.py | 生存、斩杀、损血与启发式指标 | combat evaluation 0.1.0 |
| evaluation/deck.py | 牌组结构、固定费用均值、关键牌开局概率对比 | deck evaluation 0.1.0，非完整强度模型 |
| telemetry/ | 分阶段计时、JSONL 记录、预测与实际数值对照 | 独立模块版本 |
| decision/service.py | 组合模块，生成 Codex 决策材料 | decision 0.2.0 |

依赖方向：规则和计算器依赖共享契约；搜索依赖 Simulator/Evaluator 接口；评估不调用桥接；service 负责组装；MCP 只调用 service。KnowledgeProvider 是未来知识检索接口，目前不加载 RAG。

规则修改、搜索算法修改、评估策略修改互相独立。修改模块的 VERSION；修改共用字段须更新 CONTRACT_VERSION，破坏性变化提升主版本并更新适配器。每份报告保存全部模块版本、策略完整配置、搜索预算、源会话/状态版本及状态摘要哈希。

策略配置位于 config/decision/combat.default.json，可另存配置并通过离线 CLI 的 --policy 比较。权重只是初始启发式，不是校准后的胜率或通用牌组强度。draw_option_weight 默认 0，避免在尚未实现后续价值模型时给抽牌虚构收益。

## 当前计算范围

铁甲战士支持：打击、防御、痛击、双重打击、剑柄打击、预备打击、与我一战、拆卸、闪电霹雳、突破、熔融之拳、挑衅、耸肩无视、岿然不动、巨像。数值来自实际可见描述，支持当前中英文格式。未识别数值、X 费用或未知游戏版本明确报错；未知卡不会按名称猜效果。

支持效果顺序、多段伤害、易伤取整、伤害上限、过量伤害截断、格挡、佩尔的士兵本回合首次翻倍、力量先后顺序、巨像对当前易伤攻击的减伤。可见伤害已包含当前玩家加成，不重复叠加初始力量；仅追加模拟后获得的力量。虚弱、脆弱、其他未支持能力/遗物/敌人能力阻止继续精确模拟，报告原因。模拟的反应链、完整敌方回合及战后回血仍未覆盖。

抽牌节点立即停止确定性搜索，报告为 observation_boundaries，与已知操作候选分开。提供从可见抽牌堆组成推导的目标牌概率，不读取隐藏顺序。执行抽牌后必须观察真实新手牌。当前还没有抽牌后分支的最优后续价值计算，不能声称已计算 Q(s,a)、斩杀概率或死亡概率。

7 张中 1/2/3 张目标，抽 3 张的至少一张概率为 3/7、5/7、31/35。重复实体按组合数赋权，不能把不同实体数量组合当成等概率。精确分布超出预算时用固定种子采样，报告 sampled、样本量及种子；目前未给出采样置信区间。新增实际容量截断、禁止效果抽牌、已知弃牌堆的普通洗牌边际概率；弃牌堆未知且需要洗牌则明确拒绝。概率报告假定没有抽牌/洗牌触发钩子，实际抽牌后重新观察；改变上限的未支持能力/遗物仍阻止精确模拟。

牌组比较当前只有结构和开局概率指标。能量曲线、前三回合伤害/防御、卡手、配合、升级、路线机会成本属于下一阶段。药水模拟、战斗选牌模拟、随机生成牌和 RAG 尚未接入本计算层；已有 C# 实际操作接口保持可用。

## 使用

MCP analyze_combat(max_nodes=2000, time_ms=200, top_k=5) 支持可选 opening_draw/opening_hand/later_draw/later_hand 情景输入；另有 draw_odds(total_cards, target_cards, draws)、query_game_mechanics。前者只读当前状态，默认深度 6，搜索放在工作线程，不阻塞 MCP 事件循环；报告列出覆盖缺口和首步是否在当前合法动作中。周期遗物等待候选与确定性击杀方案分列，未来费用和击杀缺少证据时不认证等待。每个实际动作仍须重新检查快照与游戏合法目录。

离线分析不连接游戏：

```powershell
& .runtime/conda/python.exe src/python/tools/analysis/analyze_snapshot.py .runtime/logs/codex-47f41415dc344acc96456d0f2e19b5d4.json
& .runtime/conda/python.exe src/python/tools/analysis/verify_calculator.py
```

默认输出 .runtime/logs/decision-analysis.json，历史报告追加到 decision-reports.jsonl。真实动作脚本新增 mcp_startup、state_read_before、action_and_game_settlement、state_read_after 计时，写入原证据文件和 action-timings.jsonl。不能在该脚本内部测到 Codex 思考耗时，不将游戏结算等待误报为模型思考。

## 验收与限制

概率测试覆盖 35 个抽牌组合、重复卡权重、边界输入、可复现采样；模拟测试覆盖易伤逐段取整、上限、顺序、遗物首次翻倍、抽牌停止；搜索测试覆盖生存优先、预算截断；报告测试覆盖版本、无副作用、暂停状态、JSONL 和数值偏差。

5 条历史动作离线对照：巨像获得 12 格挡、双重打击两段上限、拆卸、打击击杀及剑柄打击抽牌前伤害。生命、格挡、能量和敌人可见数值全部吻合，记录 calculator-archive-verification.json。此对照不证明所有机制已正确。

第一阶段单个已保存场景搜索 864 节点约 24 ms，机制扩展后同场景一次约 34 ms；机器、手牌、预算不同会改变耗时，不是整套 Codex 决策的性能承诺。测试与机制扩展均未恢复游玩。
