# 统一知识库使用说明

2026-10-14。当前实现完全本地运行，不需要 embedding、rerank、模型 key、Chroma 或 PostgreSQL。

## 目录与职责

- `data/knowledge/`：唯一正式知识资料根目录；`manifest.json` 注册活跃数据集。
- `src/python/src/autoslay/knowledge_base/`：共享仓库、快照、检索、来源解析和领域查询代码。
- `src/python/tools/kb_admin/`：知识导出、审计、索引维护和经验发布命令。
- `.runtime/cache/knowledge/<revision>/lexical.sqlite`：可重建的全文索引。
- `config/knowledge.default.json`：结果上限、关联条数、上下文预算与耗时最小样本数。

原 `autoslay.knowledge` 已改为 `autoslay.knowledge_base`，原 `tools/knowledge` 已改为 `tools/kb_admin`，项目内引用同步更新。外部 Python 脚本需要更新 import 和工具路径；原 MCP 查询工具名称保留。

本次保留 catalog、behavior、mechanics、rules、assets 等既有资料内部路径，通过 manifest 统一管理；没有复制一份百科或重写已有规则指纹。历史和观察资料仍保留，不自动成为正式检索结果。完整不可变版本目录的多文件发布属于后续扩展，本期更新兼容现有单文件原子写入。

## 读取与一致性

`Repository` 统一读取知识 JSON，同一进程中未变化的文件只解析一次，并缓存验证后的规则视图和百科投影。缓存内部对象不可修改；对外返回副本。

`KnowledgeSnapshot` 同时固定清单、已有数据集和缺失数据集。正常决策、战斗分析、确定性判断、观察台知识查询及 MCP 查询在快照作用域内运行；知识更新后，新请求获取新修订，正在处理的请求继续使用原修订。

Agent 构造上下文时复用计算报告的 `knowledge_revision`，不会重新取最新百科。修订已超出保留容量时明确报错，需要重新计算，不能默默混用当前资料。默认保留 8 个修订；缓存和内存投影有容量上限。

进程之间各有自己的内存缓存；共用同一读取实现和磁盘索引。本期没有新增 RPC 服务。快照可以防止一次决策中途变化；尚未提供把多个相互依赖的数据集作为一个事务发布的能力。

## 查询

从项目根目录运行：

```powershell
& .runtime/conda/python.exe src/python/tools/kb_admin/manage.py status
& .runtime/conda/python.exe src/python/tools/kb_admin/manage.py search "手牌溢出" --related
& .runtime/conda/python.exe src/python/tools/kb_admin/manage.py search "CARD.STRIKE_IRONCLAD" --game-version 0.111.0
& .runtime/conda/python.exe src/python/tools/kb_admin/manage.py rebuild-index
```

新增 MCP 工具：

- `search_knowledge(query, category, dataset, expected_game_version, expected_assembly_hash, language, limit, include_related)`。
- `knowledge_status()`。

原 `query_encyclopedia`、`query_behavior_log`、`query_game_mechanics`、`audit_knowledge_rules` 继续可用，内部读取共用仓库。

观察台后端提供 `/api/knowledge/search?q=...` 和 `/api/knowledge/status`，继续要求 `X-Autoslay-ReadOnly: 1` 并验证 Host/Origin。本次没有修改观察台前端布局。

检索先过滤版本、程序集、类别、数据集和语言；实体 ID、名称、别名准确命中优先，其他候选使用中文二字词和英文/ID 词的 FTS5/BM25 排序。关系由 `relations.json` 显式声明，按相同过滤条件返回一跳关联资料。没有自动推断完整知识图谱。

搜索返回引用、内容哈希、修订、审核状态和匹配类型。检索分数不代表可信概率，也不开放新模拟规则。严格过滤时，资料缺少对应版本/程序集/语言元数据也不会被当作已兼容资料。

FTS5 不可用或索引不可读时回退到内存关键词排序，返回 `backend=memory_keywords`；正常为 `sqlite_fts5`。索引按内容修订隔离；被删除的资料不会出现在新修订的检索结果中。缓存目录可以删除重建；尚未自动清理磁盘上的旧修订索引。

## 领域接口

业务代码使用 `service.SERVICE` 提供的 `get_entities`、`get_mechanics`、`get_monster`、`get_rule_view`、`get_timing_profile`、`build_context`、`search` 和 `status`。

怪物查询按构建校验并筛选进阶区间的已导出数值，仍是参考资料；不新增任意源码求值或自动规则审批。可执行规则沿用既有 Rulebook 校验与指纹机制。

## 经验与耗时

`experience/strategy/entries.json` 与 `experience/timing/profiles.json` 初始为空。不会从实战、日志或模型解释自动生成已审核知识。

经验必须提供来源引用、游戏版本、审核人和带时区的审核时间。策略声明摘要与适用条件；耗时声明 measurement_scope、环境、样本数、单位 ms、采样区间及 p50/p95。示例结构：

```json
{
  "schema_version": "knowledge-timing/1.0",
  "entries": [
    {
      "id": "example-action-profile",
      "title": "示例耗时画像，请替换为真实测量",
      "game_version": "0.111.0",
      "review_status": "reviewed",
      "reviewed_by": "审核人",
      "reviewed_at": "2026-10-14T12:00:00+08:00",
      "source_refs": ["真实日志位置及采样区间"],
      "measurement_scope": "action_settlement",
      "environment": {"device": "具体设备标识", "bridge_version": "实际版本"},
      "unit": "ms",
      "samples": 20,
      "sample_window": {"start": "2026-10-13", "end": "2026-10-14"},
      "p50_ms": 25,
      "p95_ms": 40
    }
  ]
}
```

示例数字是格式示意，不是游戏测量。显式发布命令替换该类经验的整个集合，校验通过后原子保存并保留历史：

```powershell
& .runtime/conda/python.exe src/python/tools/kb_admin/manage.py publish-experience timing reviewed-profiles.json
```

发布拒绝待审核记录和非法数值。耗时画像查询要求环境匹配，默认至少 5 个样本；无匹配或样本不足返回缺口，不假定耗时为零。

游戏触发周期和持续回合属于规则；实时回合/计时属于状态；搜索预算与请求超时属于配置；原始日志保留在 telemetry。经验发布不会将这些类别混合或自动启用规则。
