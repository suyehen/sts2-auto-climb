# 0.17.1 后端战斗选牌

用户指定后续游戏操作仅通过接口或后端代码完成，不使用键盘鼠标，也不以界面操作作为不支持流程的兜底。

能力药水与无色药水的 NChooseACardSelectionScreen 已加入战斗父动作/子选择协议：use_potion 可返回 awaiting_choice；读取 card_selection 后，每次 select_combat_card 调用游戏自身 SelectHolder 处理器；查询原药水请求直到 completed。选牌结束后确认药水已消耗、动作执行器与队列结算完成，才结束父请求。已有手牌与网格战斗选择沿用同一协议。

0.17.0 实测发现 _noSelectionTimeMsec 是静态常量，而非实例字段。0.17.1 通过反射确认其值为 350ms，结合实例 _openedTicks 判断选择是否开放。Inspector 现在显示字段 static/literal 标志及常量值。构建零警告零错误，C# 回归检查和 15 项 Python 检查通过。

真实验收：会话 0571206bb6c14545a9c348a4d434b8d2，第 6 层蛮兽战斗。play-20261009-72 使用能力药水后 awaiting_choice、busy=false；初始候选动画期间不可选，后续读取三张牌均 available=true。play-20261009-73 选择恶魔形态 completed；查询父请求 72 为 completed，药水为空，恶魔形态以本回合费用 0 入手。请求 74 正常打出，随后每回合力量增长 3。第 4 回合请求 84 击杀，燃烧之血后生命 54/80；领取 12 金币和武装，金币 150。

修复部署期间使用进程 CloseMainWindow 正常关闭，再运行 restart_game.ps1 -Deploy 加载新 DLL 并续档；未强杀进程、未修改存档、未注入键鼠输入。续档恢复房间入口检查点，会回滚房内尚未持久化的动作，因此每次重启均使用新会话状态和新的请求 ID，不重放旧请求。

随后第 9 层旧日雕像精英战，play-20261009-110 使用无色药水 awaiting_choice；111 选择滚石，父请求 110 确认 completed；112 免费打出，后续每回合伤害 5、10、15、20，均正常结算。116 武装触发 NPlayerHand.UpgradeSelect，117 选择打击并进入预览，118 确认后打击 6→9，父请求 116 completed。129 第 5 回合击杀，燃烧之血后生命 36/80。

能力药水、无色药水生成选择及武装手牌升级均已真实通过后端完成。跳过及其他战斗选择仍需各自实测。其他布局遇到不支持时应增加后端适配器。
